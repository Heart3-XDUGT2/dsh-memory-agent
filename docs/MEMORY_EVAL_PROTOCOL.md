# 公认评测协议 —— 采用版(LongMemEval,ICLR 2025)

> 起因:N0 负控档混进相关题、"检索分预测不了对错"、判定口径自造 —— 这些都是**评测构造问题**。
> 结论:**不再自造,直接采用学界最公认的那一套**。
> 出处:**LongMemEval**(arXiv **2410.10813**,**ICLR 2025**;500 题;代码/数据公开
> `github.com/xiaowu0162/LongMemEval` + HF `xiaowu0162/longmemeval-cleaned`)。
> 采用理由:它是**被后来工作实际采用**的那把尺子(Zep 2501.13956 用它、SAGE 2605.12061 用它、
> CPP 的对照也建在同一批能力档上),且有**判定器与人工专家的对照实验**。
> 配套:LoCoMo(arXiv 2402.17753)作为"超长对话/多模态"侧的数据补充。
> ⚠️ 本文只写"采用什么";幅度数字是**他们的实验**,不是我们的读数。

---

## 1. 五档能力(直接采用它的定义)

| 档 | 原文口径(意译) | 我们现有的对应 |
|---|---|---|
| **IE 信息抽取** | 从很长的交互史里**回忆具体信息**(用户或助手说过的细节) | N1 单会话事实 |
| **MR 多会话推理** | **跨多个会话综合**信息,回答涉及聚合/比较的复杂问题 | N2 多会话 |
| **TR 时间推理** | 对时间要素有意识:**显式时间提及**与交互里的**时间戳元数据** | N3 时间推理 |
| **KU 知识更新** | 用户信息**被更新后**,答的是**新值** | N4 知识更新 |
| **ABS 拒答** | **"识别那些在问『交互史里从未提及过的信息』的问题,并回答『我不知道』"** | ❌ 我们的 N0(**要换掉**,见 §4) |

⇒ **共识要点**:拒答不是"闲聊档",而是**"历史里根本没提过"的可验证属性**,正确行为是**答"我不知道"**。

## 2. 结构框架(三阶段 + 四控制点)—— 设计侧也采用

* **三阶段**:**indexing → retrieval → reading**;
* **四控制点**:**value(值粒度)/ key(键与扩展)/ query(查询改写)/ reading strategy(阅读策略)**。

这一框架把我们零散的"呈现层/检索臂/写入侧"归位:**value 与 key 在写入侧,query 在检索入口,
reading strategy 在生成前** —— 与我们 `docs/MEMORY_ARCH_DESIGN.md` 的层序**一致**,但更简洁。

## 3. 指标与判定(采用)

| 项 | 采用口径 |
|---|---|
| 中间指标 | **Recall@k 与 NDCG@k**(该基准带**人工标注的答案位置**,可算中间指标) |
| 最终指标 | **QA 准确率**,由**专家提示词的 GPT-4o judge** 判定(给出问题/参考答案/模型答案,让 judge 直接输出 **yes/no**) |
| 判定器可信度 | 论文做了 **meta-eval**:judge 与人类专家**逐档对照**(结论:整体高一致;单会话偏好与拒答两档因开放性**略有偏差**) |
| 数据卫生 | **2025/09 官方"清洗历史会话,以防干扰答案正确性"** ⇒ 与我们遇到的"负控被相关题污染"是同一类问题,官方修法是**重修数据**,不是调参 |

## 4. 它已经量出来的结论(决定"该砍哪",与我们实测同向)

| 结论 | 数字 | 对照我们的现状 |
|---|---|---|
| **value 粒度**:会话切分 | **+11.3% recall**(以"轮"为值)/ **+6.8%**(以"会话"为值) | 我们按段/轮,粒度是写入侧的事 |
| **key 扩展**:抽出的用户事实做键 | **+9.4% recall@k / +5.4% 准确率** | 我们只有 `keywords+summary` 索引 |
| **reading strategy**:Chain-of-Note + 结构化格式 | **即使召回完美,利用也非平凡**;**+10 绝对点**(3 个 LLM 上) | ⚠️ 这**大于**我们测出的"取到了没答好"余量(2/21) —— 差别在基线:他们历史 **~115k tokens**,我们只有 **208**;⇒ **杠杆大小取决于基线有多脏** |
| 长上下文直接读 | 商用助手/长上下文 LLM 在长历史上 **掉 30% 准确率** | 支持"不做全塞上下文" |

## 5. 我们要改的三处(只动评测/量台;不动生产)

1. **N0 → ABS**:负控档改成"**问的是历史里从未提及的信息**"的题,并且**先验证它真的不可答**
   (官方做法:清洗历史,排除掉干扰证据);正确行为 = **答"我不知道"**。
   ⇒ 现有 7 条里那 2 条"其实与记忆相关"的,**按官方口径就是不合格的负控题**,应当**换题或改标签**;
2. **判定 → 专家提示词 LLM judge(输出 yes/no)**,并在我们自己的小样本上做一次与人工的 spot-check;
3. **指标 → Recall@k / NDCG@k + 最终准确率**双报;中间指标需要**答案位置标注**(我们已有 `accept` 记忆集合,
   可当位置金标用)。

## 6. 必须一直声明的边界

* 我们 **21 正 + 7 负**,而该基准 **500 题**、HaluMem **3,467 QA** ⇒ 差 1~2 个数量级:
  我们的数**只给方向与优先级,不给幅度**;
* 跨协议**不排名**(SAGE 自己的声明);引用他们的数字时必须标注"是他们的实验条件"。

### 7.2 ⚠️ 判定口径抓出来的错:**我们喂给判定的"正确答案"是错的**

用官方判定器跑我们 28 条(`--ours`),结果:

| 口径 | 正样本 | 拒答档 |
|---|---|---|
| 我自己那套**引用式**(引用到金标记忆 = 命中) | **15/21 = 71.4%** | 5/7 |
| **官方判定**(答案文本是否含正确答案) | **8/21 = 38.1%** | **5/7 = 71.4%** |
| 官方判定 总体 | **46.4%(n=28)** | — |

**差 33 个百分点。抽检判 no 的条目后,原因不在判定器,在我们**:

* 我拿金标的 **`指认依据(note)`** 当了"Correct Answer"。那个字段是**为什么选这些记忆**的说明,
  会**列举全部可接受记忆**(例:校园跑那条 = "3km + 速度限制 + 手机监视器 + 一学期 40 次")。
* 官方提示词里有一句:**"If the response only contains a subset of the information required by the answer, answer no."**
  ⇒ 于是「每次3km且有速度限制不能太慢,一学期40次」(漏了"手机监视器")被判 **no**;
  「130分左右」(note 还写了"223 记了又追问过")被判 **no**;
  「凌晨一点」(note 还写了"中秋那晚/阳台之约")被判 **no**。
* ⇒ **这些答案人工看是对的**;判定判 no 是**按官方规则**对"我们给的参考答案"作出的正确反应。

**结论(重要)**:引用命中 ≠ 答对。**"引用式 71.4%"这个数字口径偏松**;要拿到可用的官方数字,
必须先把每题的**参考答案**写成**最小必需事实**(不是记忆清单)。
—— 这一步是**人工判断**,需要他确认(21 条,我可以先起草草案)。

### 7.3 判定器自检(用官方数据,两步负控)

拿 oracle 数据抽 **60 条**(5 条/题型 × 6 + **全部 30 条 `_abs`**),造两个假设:

| 自检 | 假设 | 非拒答 6 档 | 拒答档 |
|---|---|---|---|
| **阳性对照** | 假设 = 官方 `answer` | **全部 1.000**(single-session-preference 除外,见下) | 29/30 = 0.967 |
| **阴性对照** | 假设恒为 `"I don't know."` | **全部 0.000** | 29/30 = 0.967 |

⇒ **判定器把"完美回答"和"一律不知道"干净地分开了**(0.000 vs 1.000)⇒ 端到端可用;
同时暴露出两个已知噪声:
* **single-session-preference 档无法这样自检**:该档的参考字段是**评分细则(rubric)**,
  把 rubric 当模型回答当然判 no(0/5)—— 这一档要用真答案或人工;
* **拒答档有 ~3% 判定噪声**(30 条里 1 条:理想回答「I don't know」仍被判 no)。
