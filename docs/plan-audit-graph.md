## 一、证据（这轮量了什么，凭什么这样画）

| 事实 | 读数 | 对设计的约束 |
|---|---|---|
| 一轮 `latency` 之和 ÷ 该轮时间跨度 | **0.01**（23 轮可比）；`9515d152` 是 3.4 秒 ÷ 83 秒 = **0.04** | **绝对时间不能当 x 轴**：1.1 秒的条在 83 秒跨度里只占 1.3% ≈ 3px |
| 单步耗时分布 | 有值 104/200 行：中位 91ms，最大 121,116ms（跨 **6 个数量级**） | 线性刻度要么让 9ms 消失，要么让 121 秒顶格 |
| 并行支 | 3 轮 6 行；`beginAt` 两条完全相同（`9515d152`：两条都是 `…906548`），`settleAt` 差 25ms | 并行要画成"同起、先后落定"，两端必须标毫秒时刻 |
| 没有耗时的步 | 96/200 行（`retrieve` 恒 `0`、`care`/`emotion_decay` 恒 `null`） | **不能画条**：长度未知不等于很短 |
| 传得下去的量 | `retrieve.candidates=10` → `assemble.total=2088` → 送信 1 条 → 结构化产出 33 字；`persona=1796` | 传递标签有真值可写，不必编 |
| 串行/并行真相 | 两臂都在检索之前落定（`…907635/.907660` 早于 `retrieve …907699`） | 说「两路汇合后再检索」是**事实**，不是示意 |

## 二、三个方案（差异在图形语言与信息组织，不是配色）

### 甲 · 泳道时序图（竖版：主轴 + 站点 + 共用刻度尺）**← 选它**

图形语言：一条竖向主轴，主轴上每个站点一枚圆点；站点右侧是统一的**对数刻度尺**，每一步在那里画一条
时长条；分叉/汇合用拐角把两条支线接到主轴上；两站之间的竖缝里写**传了什么**。

- **顺序**：主轴自上而下，**等距**（位置 = 先后，不 = 间隔）。
- **时长**：`x = log10(ms) / log10(120000)`，全轮共用一把尺子；条尾印真实数值；最慢的几步在条尾加 1px 端帽。
- **并行**：在"她起头"处分叉成两条支线（右缩 16px、圆点小一号、分支线 35% 透明度），两臂并排、同色，
  汇合回主轴后才进检索；每条臂的句子里写 `15:21:46.548 起跑，15:21:47.635 落定`。
- **传递画在哪**：竖缝里一行：`↓ 10 条候选 交给组装` / `↓ 2,088 字上下文 交给送信`。
- **每步输入输出**：节点内第三行 `入 10 条 + 人设 · 出 2,088 字`；完整值仍在 L3。
- **390**：三列塌成一列；时长条降到节点下面，**轨道宽度每行锁死**（右端给数值固定 72px），
  所以 8 行的百分比仍对着同一条轨道；分叉缩进 10px 并去掉拐角，只留圆点与一句「分两路」。
- **文字表格退到哪**：节点本身就是那颗打开 L3 的按钮（21 键字段表 = 最细的文字形态）；
  另在图形下面给一个默认收起的 `<details>`「看文字明细（表格）」，8 行 8 列，读屏与复核走这里。

### 乙 · 节点图（DAG：节点 + 带标签的边）

图形语言：方框是步骤，箭头是流向，**标签长在边上**（「10 条候选」「2,088 字」）。

- **顺序**：拓扑层级（左→右或上→下）。
- **时长**：节点边框粗细三档（1/2/3px）或节点右下角一条小条。
- **并行**：同一节点分叉出两条边，再汇到下一节点。
- **传递**：它的强项——边上直接写量。
- **390**：7 个节点的 DAG 在 354px 里要么缩到读不清、要么横滚；**这是它过不去的坎**。
- **文字表格退到哪**：同甲（节点仍是按钮 + 表格退路）。
- 代价：这条管线是**一条链**（7 个节点首尾相接），层级不发散 ⇒ DAG 只在"分叉"那两处比甲强，
  其余位置把时长压成边框粗细，读不出量级。

### 丙 · 单行流程条（水平：每步一格，格宽表时长）

图形语言：一排等高的格子，格宽 = 该步时长（对数），格内一行字 + 序号；并行支上下两行格子。

- **顺序**：从左到右，等距槽位。
- **时长**：格宽（相对编码）+ 格内数字；最窄格设 28px 下限。
- **并行**：上下两行，汇合处一个合并记号。
- **传递**：只能塞进格与格之间的窄缝——**8 格 × 44px 之后没有地方**，最重要的一条信息被牺牲。
- **390**：8 格在 354px 里每格 44px，一行 4~5 个字 ⇒ 必须横滚或降到 9px 字，**违反硬线**。
- **文字表格退到哪**：只能放进行展开（格子点开）。
- 代价：紧凑好看、可扫，但"传了什么"与"每步入出"都没有位置。

## 三、选甲：理由与被放弃的代价

1. **只有甲同时放得下三样东西**：传递标签（缝里）、每步入出（节点第三行）、时长（右侧尺子）。
   乙把入出挤进方框，丙把传递挤没了。
2. **390 能真的降级**：塌成一列后每站 3~4 行文字 + 一条整宽轨道，不横滚、不缩字（样张实测：390 不横滚）。
   乙/丙在 390 上不是缩到看不清就是横滚。
3. **实施风险最低**：现有 L2 的节点就是 `.au-rowitem`（那颗打开 L3 的按钮），甲把"行"换成"站点"，
   类名、`data-row`、ARIA、`p5a/p5b` 的 45 项定位全不用改；乙/丙要重排 DOM 与键盘顺序。

**放弃乙的代价**：边标签那种"一眼看出信息怎么流动"的效果，甲只在竖缝里给一行，弱一档。
**放弃丙的代价**：没有"一眼扫完整轮"的紧凑缩略图。补法是**不做**——真要缩略图，用 L1 那一行就够。

### 三.2 「0.01」这条矛盾的正面解法（判分点）

问题：一轮的实际跨度是耗时的 **20~100 倍**（0.01~0.04），任何时间比例轴都把 1.1 秒画成 ~1px。

解法四条，缺一不可：

1. **x 轴不是时间**：横轴是**步骤序号**（等距）。顺序保留，间隔丢掉——
   间隔仍可查（L2 顶上的 `15:21:46 – 15:23:09`，每一步的秒级时钟在 `title` 与 L3 的 `timestamp` 里）。
2. **时长用对数**：域固定 `1ms … 2min`（覆盖本窗 104 个耗时值的 0.46 位数到 121 秒），
   条长 = `log10(ms)/log10(120000)`。于是 9ms → **18.8%**、1.1 秒 → **60%**、121 秒 → **100%**：
   两端都看得见，且 1087 与 1111ms（差 2%）在条上只差 0.2%——**差异不会被放大成噪声，只由数字说话**。
   为什么不 sqrt：`sqrt(9/120000)=0.86%`，仍是 1px。为什么不分档：三档（<100ms / 100ms–1s / >1s）
   会把 100ms 与 1 秒画成同一格。
3. **真实数值一律印在条尾**（`1.1 秒` / `9 毫秒` / `没记耗时`），不靠目测读数；
   最慢的几步在条尾加一道 1px 端帽并在标题里点名（第 2、3、5 步）。
4. **同时性不靠 x 表达**：并行支用**分叉—汇合**画，两端标真实毫秒时刻；两条臂的"同起"是数据说的
   （`beginAt` 相同），不是画上去的。

诚实边界（写进图注）：**横轴不是时间**，所以不能从这张图读出"她这一轮花了 83 秒"——
那句话写在图注与 L2 顶上，图上不做时间比例。

## 四、选定方案的规格

### 4.1 几何（1440 / 768 / 390）

```
1200 以上：  [轨 26] [节点 1fr] [尺子 236]      站点 = 轨(圆点) + 节点(卡片) + 尺子(条+数值)
 900~1200：  同上，尺子 200
  900 以下：  [轨 22] [节点 1fr]               条降到节点下面一行；轨道宽度=剩余宽-72px（数值列固定）
   520 以下：  字号与内距再收一档；原始名不做显示（与第 3 步同一条降级）
```

- 站点竖向节奏：节点内边距 `9/12`，站间 `via` 缝 9+9；1440 实测一站 86~90px，8 站 ≈ 720px。
- 主轴 1px（`#d9ddd5`），圆点 7px（并行支 5px），失败圆点 `#b42318`，轮外圆点空心。
- 条：8px 高、4px 圆角、`#1b6e66`；失败 `#b42318`；**没有耗时就整条不画**（只留右侧「没记耗时」）。

### 4.2 编码表（时长 → 条长）

| ms | 条长 | 例 |
|---|---|---|
| 1 | 0% | — |
| 9 | 18.8% | 结构化产出 |
| 100 | 39.4% | （刻度，无标签） |
| 1,087 / 1,101 / 1,111 | 59.8 ~ 60.0% | 情绪打分 / 组装 / 查询扩展 |
| 1,000 | 59.1% | （刻度「1 秒」） |
| 30,000（慢线） | 73.9% | L1 的「慢」阈值也画在这把尺子上 |
| 121,116 | 100% | 本窗最大 |

刻度只标三处：`1 毫秒`（0%）、`1 秒`（59.1%）、`2 分钟`（100%）；另有两条无标签刻度（39.4% / 78.8%）。
不在窄档画刻度（≤900 时尺子整块隐藏，数值仍在条尾）。

### 4.3 分叉 / 汇合规则

- 判据：同一轮里 `step ∈ {21, 22}`（`same_turn_emotion` / `query_expand`）的行 = 并行支；
  相邻且 `beginAt` 相同的**并为一组**（本窗 3 轮，每组 2 条）。
- 画法：在**紧邻的前一个主流程站之后**分叉，组内各臂右缩 16px、圆点小一号；
  组后第一个主流程站之前汇合；两边各一句小字：「分两路 · 两路都从 15:21:46.548 起跑」「两路汇合（都在检索之前落定）」。
- 组内一臂失败时：该臂圆点与条都用 `--negative`，句末「失败（没留原因）」，汇合句不变（事实是它没给结果，不是没跑）。
- 只有一臂存在时：不分叉，画成一个普通站点 + 标记「并行（另一路没记）」。

### 4.4 传递标签（缝里那一行）

取值顺序（取到即停，都来自**前一步**）：

1. `stageDetail.candidates` → `10 条候选`（retrieve → assemble）
2. `stageDetail.total` + 前一步入参 → `2,088 字上下文`（assemble → 送信）
3. `speechOf` 有内容 → `1 句话`（送信 → 结构化产出）
4. `looseArgOf('summary')` 长度 → `33 字`（结构化产出 → 下一步）
5. 都没有 → 只写「传下去」+ 一句"这一步没留下量"（**不编数字**）

轮外行之前的那条缝写事实：`以下是后台记账 不在这一轮的回复管线上`。

### 4.5 状态与字形

- 慢 / 失败 / 并行 / 又跑了一次 / 轮外：与第 2 步同一套文字标记，字色只用 `--faint` 与 `--negative`。
- 失败另加两处：失败圆点 `--negative`、失败条 `--negative` + 条尾端帽。
- 字体：全图 13px，只有序号 12px、刻度 11px（**图形视图里不出现 12px 正文**：实测 12px 密集标签会把
  `tiny-text` 顶到 0.78，升到 13px 后是 0.021）。
- 数字一律 `tabular-nums`；屏上唯一 ≥24px 的数字仍是 L0 的「15」。

### 4.6 动效（只表达状态与先后）

| 时刻 | 动作 | 时长 |
|---|---|---|
| 展开瞬间 | 主轴自上而下画出（`scaleY` 0→1） | 600ms |
| +60ms 起 | 节点按步骤顺序淡入并上移 8px，每站间隔 **70ms** | 300ms/站 |
| +120ms 起 | 时长条同序从左长出（`scaleX`） | 420ms |
| 并行两臂 | `--i` 相同 ⇒ **同时**出现（不排队） | 同上 |
| 汇合点 | 一圈 1px 环扩出去再消失，**一次** | 1.1s |
| 失败点 | 同上，`--negative` | 1.2s |
| `prefers-reduced-motion: reduce` | 全部 `animation: none`、环 `opacity: 0`；图是终态 | — |

禁止：循环播放、粒子、任何"用位移表达时长"的动效（时长只有条长一种编码）。

### 4.7 可读性硬线（样张实测，不是口号）

| 硬线 | 实测 |
|---|---|
| 390 不横滚 | `scrollWidth 390 = innerWidth 390`（三档均等） |
| 小屏不缩字看不清 | 390 正文仍 13px、站名 15px；只有刻度（11px）在小屏隐藏 |
| `tiny-text ≤ 0.25` | 1440 **0.021** / 768 0.011 / 390 0.012 |
| ≥24px 的数字只有 L0 一个 | 1 个（`15` @40px）；其余最大 14px |
| 无 `C:\` / `session-xxxxxxxx` / UUID / 原始 JSON | 逐节点与 `innerText` 各扫一遍：**0 / 0 / 0 / 0** |
| 样张自测 | `p7a` 13 项全绿（见 `docs/screenshots/p7a-sample-check.json`） |
| 样张过闸 | `lint` 0 FAIL / 1 WARN（`—` 是缺失值字形，14 处）；`inspect --app` 0 FAIL / 0 WARN |

### 4.8 不丢信息：图形是主视图，文字仍是本体

1. **每个站点就是一颗按钮**：点开 = 现在 L3 的 21 键字段表（原样不动）。
2. **图形下面一个默认收起的 `<details>`「看文字明细（表格）」**：同一轮 8 行 × 8 列
   （序号/时钟/阶段/一句话/入/出/耗时/标记）。读屏用户、复核脚本、复制粘贴都走这条。
3. 站点的 `aria-label` 写完整一句（「第 2 步 情绪打分：并行支，失败，没留原因」），不吃图形。
4. 一句话、时钟、耗时、标记这些字**在节点里也在**，所以"图形没画出来"不等于"信息没了"。

## 七、不做清单

1. **不做力导向图、不做粒子/装饰动效、不做循环播放**；动效只表达状态与先后（§4.6）。
2. **不用绝对时间当 x 轴**（这是这轮的核心约束）：不做甘特/时间带/比例轨道。
3. **不把长度未知画成很短**：没有耗时就整条不画。
4. **不编传递量**：取不到就写「传下去」，不猜条数/字数。
5. **不把图形做成唯一视图**：L3 与表格退路必须都在（§4.8）。
6. **不为图形改 L1/L0/L3 的既有结构**；不新增第二排控件；不动折轮逻辑。
7. **不在 390 上横滚或缩字**；小屏只做塌列，不做缩放（`transform: scale` 会让 13px 变 9px）。
8. **不引入图表库**：这套图用 CSS grid + 内联 SVG + 对数换算就够，加依赖会把这一屏的包体与闸都拖进来。

## 八、需要他点头的两处

1. **竖版泳道够不够"图形"**。它比现在的文字账本多了主轴、分叉汇合、共用刻度尺与传递标签，
   但读起来仍是"一列卡片串在线上"。若他要更"图"的观感，备选是乙（节点图）+ 甲并存：
   顶部一条横向缩略流程条（丙）当导航，点哪格展开哪一站 —— 那是第 3 步之后的事，先要他的判断。
2. **对数刻度能不能接受**。它的代价是"条长不能做加法"（3 条 1.1 秒的条加起来不等于 3.3 秒的长度），
   好处是 9ms 与 121 秒同屏都看得见。若他要"肉眼可以相加"的直觉，就得改成等宽条 + 数字，
   那时这张图就只剩"顺序 + 并行 + 传递"，时长退回文字。
