## 0. 先记住我们自己的三条实测(文献要跟它们对齐)

1. **RRF 融合三次被否**:同族打平(85.7)、异族 = BM25(81.0)、N5 单量 100→66.7。
   机制:RRF 奖励"各臂排名一致",而 **N4/N5 要的是"最新那条"** ⇒ 天然对冲。
2. **候选够、编排不够**:逐概念捞人门槛修对后真捞回 **600→69 次**,**判定一动不动**;
   而 N4 覆盖 **26 → @20 94%**(答案全在池里,进不了 top5)。
3. **N2 = 真找不到**(33% 连 top20 都进不去)、**N4 = 装不下**(94% 兜底,红线)。
   ⇒ 主战场 **N2/N3**,护城河 **N4**。

## 2. 逐篇要点(只留能用的)

### MemX(最贴我们的一篇)
* **粒度三档**:session / round / **fact(用 DeepSeek-Chat 把每轮拆成原子陈述)**。
  ⟶ 我们存的是 `summary + keywords`,**没有原子事实层**;ENGRAM 也是 typed records。
* **四因子重排 + 分数归一化**:重排因子是可解释的数值(不是再投一票)。
* **低置信拒绝规则**:整批不给 ⇒ 拒绝注入(我们已有"没有命中任何记忆"的标注,但只在渲染层)。
* **存取与检索分离(§3.7)**:与我们的「L0 强制占位 ≠ 被想起」是同一条纪律(硬塞率 100% 是设计)。
* **它的软肋**:LongMemEval 上 **temporal / multi-session 只到 ≤43.6% Hit@5** —— 与我们 N2/N3 的痛一致;**时间档是公认难点**。
* ⚠️ 它用 **RRF** 却是正收益 ⇒ 关键可能在"四因子重排 + 低置信拒绝"把 RRF 的"最新优先"伤害兜住了。
  **这条值得优先读全文**(它最接近"证明 RRF 可救"的反例)。

### ConvMemory v2(**机制可直接嵌我们的红线**)
* 级联形状:先取候选 → **保护集(如 top-10)整体保留** → 重排**只在保护集内部换序**
  ⇒ **Recall@K/Hit@K 由构造成立、不降**;提升体现在 MRR。
* 它的 scorer 是**训练出来的**(教师蒸馏 0.6B/4B)⇒ 我们**不搬模型,只搬形状**:
  用我们现有的结构化调用当"listwise 重排器",**但只允许它在保护集内换序**。
* v1 的诚实负面结论也值得学:「temporal window **not load-bearing**」——自己把不成立的机制公开否掉。

### Training-Free Fusion(**决定我们"要不要重排"**)
* dense + BM25 **分数级**融合 ⇒ 大胜单路;**再套一个通用 cross-encoder 重排 ⇒ 反而 -6.9 pp**。
* 收益集中在 **multi-hop / temporal**;在"词法已经饱和"的集子上增益不显著。
  ⟶ 对我们的启示:①融合要在**分数**层,不是**排名投票**(我们 RRF 死因);②**别急着加通用重排器**;
  ③预期收益要落在 **N2/N3**,若量出来不落这两档就是没生效。

### Chronos / MemGAS(**两条低成本结构性改进**)
* Chronos:事件日历(把 `occurred_at` 组织成"日历视图")单独贡献 58.9% ⇒ **N3/N4 的结构化时间索引**。
* MemGAS:按查询**选粒度 + 调 top-K** ⇒ 直接回应我们"N4 覆盖 26→94、top5 装不下"。

## 4. 升级架构的候选路径(三层,先做零依赖的)

**L1 · 零依赖(建议先做,不动表结构)**
1. **A 召回保全级联**:把"重排"限定在保护集内换序 —— 先解决"编排"又不碰 N4 红线;
2. **B 多答案档口径**:量台按"命中比例 + topK 曲线"报,并把注入 topK 从固定 5 改成按答案集规模自适应;
3. **C 事件日历**:给 `occurred_at/temporal_status` 加一个"日历"视图(或注入时按时间线组织)。

**L2 · 需要模型**
4. **H 分数级融合**(等 embedding 来源定了:本机无模型;主包又不能加载 sqlite 扩展 ⇒ 走 python 侧 HTTP,保 stdlib-only);
5. **F 迭代检索**(用现有结构化通道,注意延迟预算)。

**L3 · 结构性(大改)**
6. **D 原子事实 + 类型化存储(episodic/semantic/procedural)** + **E 集合合并**
   —— ENGRAM 的证据是"不需要复杂架构就能 SOTA",而 MemX 的证据是"四因子重排 + 低置信拒绝"值钱;
   两者共同点:**类型化 + 简单合并 + 可解释重排**,不是加更多臂。

### 7.3 对我们的四条结论

### 7.4 MemX 逐节精读(全文已取,2026-09-29)

**§3.1 管线**:`Embed(Qwen3-0.6B,1024 维)` → 并行两路[向量(DiskANN/暴力余弦) + 关键词(FTS5)]
→ **RRF(k=60)** → **四因子加权重排** → **z-score + sigmoid 标定** → **拒绝闸** → 去重 → top-k
→ 写回检索统计。实现:Rust + libSQL(单文件)。

**§3.2 数据模型**:`memories`(content / embedding / type / tags / metadata / importance
+ **access_count / last_accessed_at** + **retrieval_count / last_retrieved_at**);
`memory_links` 七种关系(similar / related / contradicts / extends / **supersedes** / caused_by / temporal)
—— **图存在,但没进检索路径**(与我们图通道的地位一致)。

**§3.3 Algorithm 1(确定性固定阶段)**
```
e_q = Embed(q)
V = VectorRecall(e_q, n)          # 余弦
K = KeywordRecall(q, n)           # FTS5
C = RRF(V, K)
S = FourFactorRerank(C)
Ŝ = ZScoreNormalize(S)
if K == ∅ and max_{m∈V} sim(e_q, e_m) < τ:  return ∅    # 低置信拒绝
D = Dedup(Ŝ)                      # 内容 + 标签签名
R = TopK(D, k); RecordRetrievalStats(R)
```

**§3.4 四因子重排(最值钱的一节)**
`score(m) = 0.45·f_sem + 0.25·f_rec + 0.05·f_freq + 0.10·f_imp`

| 因子 | 信号来源 | 权重 |
|---|---|---|
| `f_sem` | 语义相似度(**取自 RRF 分**) | **0.45** |
| `f_rec` | **新鲜度**(优先 `last_retrieved_at`,回退 `created_at`) | **0.25** |
| `f_freq` | 频次(优先 `retrieval_count`,回退 `access_count`) | 0.05 |
| `f_imp` | 重要度(显式标注) | 0.10 |

* 权重**和只有 0.85**:因为随后 z-score 归一化去掉绝对尺度,**只有比例有意义**,余量留给未来因子;
* **新鲜度 = 指数半衰期**:`f_rec = 2^(−d/30d)`(**h = 30 天**),平滑、**无硬切**;
  频次 = 对数归一 + 封顶:`min(1, ln(c+1)/10)`;
* 标定:**先 z-score(在候选集内)、再 sigmoid**;`σ < 1e-6` 时跳过以防除零 ——
  **"先标定、再谈阈值"**,正是我们 RT11"门槛与尺度不配对"的病根解药;
* **纪律**:排序用 `retrieval_count`(被检索用到)而非 `access_count`(被人看过),
  新鲜度同理用 `last_retrieved_at` —— **防"管理员式访问"污染有用性信号**。

**§3.5 去重(两层)**:①内容完全相同 → 留最高分;②**标签签名**(`type` + 排序后 tags,
如 `procedural::ops|release`)→ **每个签名最多留一条**;无标签者**豁免**。

**§3.6 拒绝闸**:`K 为空 且 max 向量相似度 < τ` ⇒ **返回空集**;τ = **0.50**(§5.3 阈值扫确定)。
用少量召回换"不可答查询"上的假阳性下降 —— 与我们的**负控档**同一条纪律。

**§3.7 存取分离**:access(显式读:`access_count/last_accessed_at`)vs retrieval(被检索返回:
`retrieval_count/last_retrieved_at`)—— **防"读过"抬高"有用"**。

**§5.6 消融(表 9;两个自建场景合并,n_rel=37 / n_miss=6)**

| 配置 | Hit@1 | Hit@3 | TC@k | Miss-Empty | Miss-Strict |
|---|---|---|---|---|---|
| V(只向量) | 94.6 | 94.6 | 81.0 | 0.0 | 83.3 |
| V+K(加关键词 + RRF) | **94.6(全指标零变化)** | 94.6 | 81.0 | 0.0 | 83.3 |
| V+K+Rej(加拒绝闸) | 94.6 | 94.6 | 81.0 | **66.7** | 83.3 |
| Full(加标签去重) | 94.6 | **97.3** | **83.2** | 66.7 | 83.3 |

* ①**"加关键词 + RRF 在任何指标上都没变化"** ⇒ **独立复现我们的 RT10 结论**(RRF 在那个语料上也没增量);
* ②**拒绝闸是 Miss-Empty 的唯一贡献者**(0 → 66.7%),Hit/TC **一动不动** ⇒ 对不可答查询是**免费的**;
* ③去重 +2.7pp(Hit@3)—— 但对**无标签原子事实**是 **−5.0pp**(下详)。

* session→round 仅 **+2.4pp**,round→fact 却 **+24.6pp** ⇒ **"每条记录的语义密度"才是首要驱动**;

  同会话的并列答案(共相关事实)**:fact 集里全是无标签 `semantic`,签名完全相同 ⇒
  **又一例"加了组件反而更差"的公开案例**。

**§5.5 延迟**:≤1,014 条时关键词检索 **< 3 ms**,延迟由 embedding API 主导(545 ms);

### 7.5 由 §7.4 修出的四条结论(取代 §7.3)

1. **上游粒度 > 管线环节**。它的原话:在大规模记忆库上,**"投在上游切分与事实抽取的回报,
   大于增加检索管线阶段"**;round→fact +24.6pp,而我们还在讨论"再加一条召回臂" ——
   **力气该花在抽取粒度上**(对应 §3 候选 D,优先级应提到最高)。
2. **RRF 零增益有了第二份独立证据**(V→V+K 全指标不动)⇒ RT10 的否决不是孤例。
3. **拒绝闸可以照搬形状,且要独立成模块**:`关键词空 ∧ 最大相似度 < τ` ⇒ 空集;
   **先跑阈值扫定 τ**,再用 miss 查询(负控)量假阳性 —— 我们目前只有渲染层一句标注。
4. **去重必须 data-dependent**:带标签/模板数据有用(+2.7pp),**无标签并列答案有害**(−5.0pp,
   挤掉共相关事实)⇒ 我们的**多答案档(N2)恰是"并列、共相关"那一类,不能盲抄签名去重**;
   我们自己的 R5 去冗余把一切压成 67/67/67 也是同一个病。
5. (补)**"先标定、再阈值"**:z-score + sigmoid 让跨查询的 τ 可比 —— 这正是我们 RT11
   "门槛 0.1 与词元尺度不配对"的真正解药。

### 8.1 缺口 A:topK /"装不下"/多答案档

## 9. 第三轮:四篇全文精读(2026-09-29 深夜)

### 9.1 AutoViewMem(2609.21940)—— "视图"是**投射**,不是粒度
* **定义**:一个 view = **轻量 schema(name + slots + 抽取模板)**,模板指示 LLM 从对话里填字段。
  **view 与粒度正交**:"**granularity 控制记忆单元大小,而 view 定义对同一批证据的语义投射**"
  (重要区分 —— 我上一轮把两者混为一谈了);
* **在线 Diverge–Converge**:每 **50** 个 chunk 让 LLM 提 **10** 个候选视图 → 用 **DPP** 选出
  **10 个低重叠**活跃视图 → 按其模板抽取;每条记忆带 **出处 span + 时间戳 + 视图标签**;
* **核心主张**:在**写入期**消除语义纠缠 ⇒ 之后**标准全局 top-K 就够**,不需要路由或迭代检索;
* **消融(固定预算 K0 = 30)**:

  | 变体 | Judge ↑ | no-pos% ↓ |
  |---|---|---|
  | Full | **0.837** | **5.14** |
  | 单视图(去多视图组织) | 0.774 | 5.53 |
  | 去 DPP(随机选视图) | 0.777 | 7.03 |
  | 去图整合(consolidation) | 0.801 | **9.83** |

  ⇒ ①**只做结构化抽取、不做多视图组织是最弱一档**;②**冗余整合在紧预算下关键**;
* **预算敏感性**:随 top-K 先升后**饱和**;AutoViewMem **在小预算下优势最大** ——
  "聚焦视图让**早期**上下文更不噪"(直指我们"N4 覆盖 26→@5 装不下");
* **它的诊断量 `no-pos%` = "检索池里没有任何相关证据的查询占比" ⇔ 我们的覆盖@k**;
* 案例:同一句模糊对话,三个视图抽出三个侧面(活动/动机/陪伴)⇒ **多视图 = 同一证据的多重投射**。

### 9.2 双时态记忆库(2607.26520)—— 一个反例 + 一次**修正**
* 双时态:`valid time` / `transaction time`;两个索引(当前状态 + 全历史);**过取 10×k 再事后过滤**;
* 结果(60 问):**知识更新 80% R@10**;**时间推理:时间旅行 50 → 37.5%**;**多会话 0% R@1 / 30% R@10**;
  整体 46.7%;
* **post-filter dilution**:过取的 100 条里很多是"旧版本",过不了时间过滤;幸存者
  **按相似度重排、没有新鲜度信号** ⇒ 答案跌出 top10。作者定位为
  "**过取设计的可复现失败,不是时间模型本身的失败**";
* ⚠️**修正我上一轮的读法**:它报告 **R@5 ≡ R@10(每一档都相同)** ⇒ 在它的语料 + 1024 维 dense 检索下,
  **失败几乎都是"召回不到",不是"排不进"**。而我们 N4 是**"排不进"(覆盖 26→94)**。
  ⇒ **两种失败模式并存,取决于"索引单元 + 检索器"**:
  * 词法检索 + 短单元 ⇒ **小 k 的排序质量**是瓶颈(我们的情况);
  * dense 检索 + 长对话 ⇒ **召回**是瓶颈。
* 另一条:**"多会话/计数型问题无法靠检索本身回答"**(他们只有 30% 靠检索拿到)⇒
  **我们 N2 可能不是"排序问题",而是"聚合问题"**。

### 9.3 Chronos(2603.16862)—— 双日历 + **工具化**检索
* 部件:①**事件抽取**(subject-verb-object 事件元组 + **多分辨率时间**:显式日期精确保留、
  相对引用按会话时间戳换算、模糊表达解析成区间)②**动态提示**(问题条件化的检索指引)
  ③初始检索:向量 top-100 → **交叉编码重排(Cohere Rerank v3)** → top-15 → **上下文扩张(±1 轮)**
  ④**带工具调用的 agent**:`search_turns`/`search_events`(向量)+ **`grep_turns`/`grep_events`(精确词法)**;
* **注意**:它的词法能力是**工具**,不是"融合进一个排名" —— 与我们在 RRF 上的失败路径不同;
* **维护两条日历**:事件日历(结构化时间区间)+ 轮次日历(原文对话);
* 结果(GPT-4o):LongMemEvalS **92.60%**(+7.67% 相对);Chronos High **95.60%**;

### 9.4 LycheeMemory V2(2608.12990)—— 分段 + 索引族 + **选择栈**
* **在线语义分段**(替代机械窗口):边界分 = 语义惊讶 + 内聚下降 + token 压力 + 轮次压力;
  **全 embedding 判定、无 LLM**;δ=0.50;平均 **5.8 轮/段**;
* **类型化记录**:自然语言陈述 + 类型 + 实体 + 主题 + **时间范围** + 原文出处链接;
* **结构化索引族(确定性,零生成成本)**:entity / topic / entity-topic / **temporal** / **event-frame**;
* 查询期:**planner 把问题分解成多条 recall 路线** → 分别从语义记忆 + 结构化索引 + 时间索引 + 原文取
  → **路线级重排 + 融合 + 多样性选择**;
* 结果:LoCoMo **89.22** / LongMemEval-S **92.20**;**multi-hop +27.3pp、open-domain +25.0pp、

* **消融(最有用的一张)**:

  * 边界阈值敏感性:全区间仅差 **1.04pp** ⇒ 增益来自**设计**,不是调参。

### 9.5 四篇合起来(第三轮结论)
1. **写入期 > 查询期** —— 第四份独立证据(LycheeMemory 构造侧消融 + AutoViewMem 视图 +

3. **时间必须做成索引**(事件日历 58.9%;temporal/event-frame 索引;post-filter 反例)⇒

4. **多会话聚合是"聚合问题",不是"排序问题"**(双时态 30% ↔ Chronos 91.73%,差别在

   ⇒ **同一个"覆盖@k"在两种系统里含义不同;引用别家数字必须带上检索器**。

### 10.1 分数级融合 vs RRF(2606.04194)—— **修正:融合不是死的,RRF 才是**
* 配方:`s_fuse = α·z(s_BM25) + (1−α)·z(s_dense)` —— **先 z 归一,再线性加权**,
  单个 leave-one-conversation-out 权重 α;**训练免费、纯 CPU**;
* 结果(LoCoMo):**Hit@1 +8.8 ~ +17.2 pp**(对 late-interaction 单路;六种编码器;全部 p<1e-4);

* **边界(对我们最关键)**:
  * 编码器越大,融合的边际收益越小;
  * **在 LongMemEval-S 这种"词法已饱和"的语料上,融合相对 BM25 的净增益小且不显著** ——
    **与我们"融合零增益"的实测完全吻合**(我们就是中文小语料的词法区间);
  * 分类别:**late-interaction 赢在 multi-hop/temporal,BM25 赢在 adversarial** ⇒
    融合的价值 = **把各自赢的那些拿过来**;
* 另一条:**turn isolation(max-sim) > early(mean-pool)**;
* ⇒ **结论**:RT10 否掉的是 **RRF(排名级融合)**;**分数级 + z 归一 + 线性加权**在文献里

| temporal-reasoning | 33.86 | 30.71 | 33.07 | 22.83 | **41.73** | 51.96 |
| single-session-preference | 40.00 | 33.33 | 43.00 | 33.33 | **46.67** | 63.33 |

* **不同查询类型偏好不同粒度**:时间 → session;知识更新 → turn;偏好 → summary;
* **路由在每一档都胜过任何单一粒度**(知识更新 51.39 vs 单粒度最好 41.67;时间 41.73 vs 33.86);
* 机制:对每个粒度算相似度分布的 **Shannon 熵**,**按反熵加权** `w_g ∝ 1/H_g`;
  GMM 做 accept/reject 关联;Personalized PageRank;**无手调**;
* 成本:构建 52.9M 输入 token ≈ 语料本身(基线 62~111M);多粒度只多 **10% RAM**(27MB/266MB)。

### 10.3 重排:标定是"能不能设阈值"的前提(MemReranker,2605.06132)
* 三个病:①**分数标定失败**(BGE-Reranker 一类分数**左偏堆在 0 附近** ⇒ 生产系统**根本没法设阈值**);
  ②推理力缺失(时间约束、数值比较、因果);③指令感知缺失(不能用对话上下文消歧);
* 解法:LLM 教师蒸馏 + **Elo / Bradley-Terry 标定打分**;MemReranker-4B **0.737 MAP**;
* ⇒ **与我们 RT11 撞的墙一模一样**:不是门槛设高了,而是**分数没标定,阈值本身不可设**。

### 10.4 召回保全级联:对,但**我们的量台看不见它**(ConvMemory v2,2606.10842)
* 形状:v1 密排 top-500 → 轻量重排(3.6M 参)得 top-10 + 尾;**v2 只重排"受保护 top-10"**
  (每问 10 次 pair 打分),尾部原样拼接 ⇒ **R@10 / H@10 由构造等于 v1**;
* 数字:**FULL MRR 0.5824 → 0.6560**(+0.0734,95% CI [0.0645, 0.0827]);追到 mxbai_top500
  的 ~85%,延迟只要它的 **1/6.72**(11.867 ms/q);oracle 上限 **0.8415**;
* 它的结论句:`v1 的高召回候选池 + v2 的精确重排 > mxbai 直接重排一个"自身 top-10 已丢金"的 pool`;
* 自认局限:天花板被 **v1 的 top-10 召回**卡死;**评测止于检索**,重排增益**是否传导到端到端答案质量未证**;
* ⚠️**对我们的要紧含义(仪器缺口)**:这类"召回保全"改动**在我们现在的判据下必然显示为 0 效果** ——
  我们的判据是**答案集覆盖@k**,对"同一集合内换序"**天生无感**。
  ⇒ **量台要加"顺序敏感"读数**(MRR@k / NDCG@5 / 首个答案位置),否则这类最优改动**量不出来**。

### 10.5 第四轮结论
1. **修正**:RT10 否掉的是 **RRF**,不是"融合";文献最优是 **z 归一 + 线性加权的分数级融合**;
   但在**词法饱和语料**上它相对 BM25 净增益**不显著** —— **我们属于这一类**,要有预期;
2. **多粒度 + 按查询路由**是**零手调、每档都涨**的机制(MemGAS 表 7),我们引擎里已有多种表示,
   **可以直接试**;
3. **阈值的病根是"分数未标定"**(MemReranker 明说 BGE 类分数左偏 ⇒ 阈不可设),与 RT11 一致;
4. **仪器缺口**:"召回保全"这类编排改动需要**顺序敏感读数**才看得见 ⇒ **量台要加 MRR/NDCG**;
5. **重排收益 → 答案质量之间还有一段未被证明的路**(ConvMemory v2 自己的局限)⇒
   引用"重排涨分"时必须区分**排名指标**与**答案正确率**。

### 10.6 优先级(第四次更新)
1. **量台补"顺序敏感"读数**(MRR@k / NDCG@5)—— **先修尺子**,否则后面几条都量不出效果;

## 11. 第五轮:评测框架与"结构 × 检索法"

> 全文:`.scratch/2605.20926.txt`(MemConflict,117k 字)、`.scratch/2412.15266.txt`(Structural Memory,50k 字)。

### 11.1 MemConflict(2605.20926)—— 一套**可以直接抄的评测框架**
* 把"记忆有效性"定义为 **query-conditioned fitness-for-use**,形式化三类冲突:
  **dynamic**(随时间变化)↔ 我们 **N4**;**static**(互相矛盾)↔ 我们 **N5**;
  **conditional**(依赖上下文才适用)↔ 我们 **N6**;
* **两层协议**:**黑盒**最终答案 + **白盒**记忆检索与排序 —— 指标
  **SEH@3**(top-3 里有没有支撑证据)、**SRS**(支撑证据的排序分);
* **核心发现**:**"答案正确率常常与记忆检索/排序质量脱钩"**;并把错误**分解**为
  **检索失败**(金标不在检索集里)vs **利用失败**(金标检索到了、答案还是错);
* 敏感性:更长的历史、**语义相似的干扰项**、隐式查询、更大的"冲突距离"都会拉低性能;
* 对比系统:MemOS / Letta / A-Mem / LangMem(**专精 dynamic 冲突**)/ Memobase;
* ⇒ **对我们直接可用**:①白盒指标(**SEH@3 / SRS**);②**"检索失败 vs 利用失败"的分解**
  (我们目前只量"覆盖",分不出这两类);③**干扰项注入**(我们 19 条负样本里没有
  "语义相似的非目标记忆"这一类)。

### 11.2 结构 × 检索法(2412.15266)—— **K 有最优点,迭代检索稳赢**
* 四结构:**chunks / knowledge triples / atomic facts / summaries** + **mixed**;
  三检索法:**单步 / 重排 / 迭代**;
* 结论:
  1. **混合结构一致最好**(迭代 + 混合:HotPotQA F1 **82.11**、2WikiMultihop **68.15**);
  2. **chunks 与 summaries 擅长长上下文**(阅读理解 / 对话理解);
     **triples 与 atomic facts 擅长关系推理与精度**(atomic facts 在 HotPotQA **81.29**,
     triples 在 2WikiMultihop **62.06**);
  3. **迭代检索在所有场景一致胜出**(改查询 → 再检索);
  4. **混合结构对噪声最有韧性**;
* **K 的敏感度(LoCoMo)**:chunks 到 **K=50** 饱和;triples / atomics / summaries 升到 **K=100**,
  **到 K=200 反而下降** ——"**检索过多带来的噪声**";且"**取少量高相关记忆,能胜过取更多再重排**";
* 迭代参数:每次交互取 **T 条,T=50 饱和**;迭代轮数 **N=3 饱和**(LoCoMo);
* ⇒ **对我们直接可用**:①**k 不是越大越好**(有最优点 ⇒ 我们"top5 装不下"**不等于"调大 k 就好"**);
  ②**迭代检索**是零依赖、一致正收益的一步(与我们已有的"查询扩展"通道天然衔接);
  ③原子事实 / 三元组对"关系与精度"最有用。

### 11.3 第五轮结论
1. **量台要补三样**(都来自别人的框架,且**不改生产代码**):
   **顺序敏感读数**(MRR / NDCG@5)、**白盒支撑指标**(SEH@3 / SRS)、**干扰项注入**(语义相似非目标),
   并把错误**分解成"检索失败 / 利用失败"**;
2. **"把 k 调大"不是答案**:LoCoMo 上 K=200 反而掉,最优在中段;
3. **迭代检索**是本轮最便宜的一致正收益(单步 → 迭代;零新依赖);
4. **结构多样化(混搭)**比"选一种最好的结构"更稳(噪声环境下尤其)。

### 11.4 优先级(第五次更新)
1. **量台升级**(顺序敏感 + 白盒 SEH@3/SRS + 干扰项 + 失败分解)—— **先修尺子**;
2. **标定 + 拒绝闸**(MemX / MemReranker);

4. **多粒度 + 熵路由**(MemGAS 表 7);
5. **结构化索引族 + 事件日历 / 双时间**;
6. **z 归一分数级融合**(替 RRF;注意词法饱和的预期);

### 12.1 TRACE(2607.00339)—— 直打 N4 / N5 的机制
* 它的问题陈述几乎逐字就是我们的 N4:"**计划被修改、偏好变了,后面的消息经常 supersede 或 contradict
  前面的**;现有长期记忆管线把记忆当独立文本/向量对象 ⇒ **常常取回"语义相似但已过期"的证据**";
* **离线建图四步**(起点是会话级 summary 的 note memory 𝒩):
  ①会话级**事件蒸馏** → ②**跨会话链接(候选门控)** → ③**时态与演化边推断** → ④**层级注入**
  (session / topic 作结构顶点);
* 边类型:**temporal / causal / update / contradiction**;
* **有效性标注**:被取代的事实 `v(e)=0` —— 历史查询仍可取,**当前态回答里降权**;
* 查询期:`C = C_note(原文,词法/向量)+ C_path(图路径:关系结构 + 时间有效性)+ p_q(按问题形状的计划)`,
  **刻意分离"词法召回"与"证据重建"**;
* 数字(**专建 59 条 Stress Test**:被取代事实 / 矛盾 / 链式修订):
  * TRACE **valid accuracy 0.390**、**strict net +0.314**(比 Nemori +9.4 pp、比 A-Mem +4.2 pp);
    **过期泄漏 0.076 = 与 Full-Context 持平**(Nemori 0.102 / A-Mem 0.085),而 **token 少 5×**;
  * **update-aware seed 消融**:strict net **+0.314 → +0.212(−10.17 pp)**、valid **−8.47 pp**、泄漏 **+1.69 pp**;
    LoCoMo 上整体 −0.93 pp,但**集中在 Open-Domain −7.29 pp**(偏好频繁演化的类别);
  * 机制句(我们的原病):"**当最新版本用词与查询不同(偏好变化的常见形态)时,
    系统会取回更旧、词法更相似的那一版**";
* 可解释性三层:**Graph Edge Audit 94% 事实 / 89% 边类型**(错误集中在同时间戳的 `temporal_before`);
  **Cue Glanceability 81.8% vs 语义-only 18.2%(+63.6 pp)**,误导率 22.7% vs 54.6%;
  **Path Faithfulness 42.5%**(SH 65 / MH 45 / OD 36 / Temporal 22.5);
  独立规则校验器 65.4% vs 37.8%(+27.6 pp),且**留了一条 flat 的负控(+5.9 pp ≈ 平)**;
* 边密度:**update + contradicts 边在 LoCoMo 上 185~362 条**,小规模会话上只有 1~8 条
  ⇒ **"取代 / 矛盾"在真实对话里是高频结构**,不是边角料。

### 12.2 CPP(SIGDIAL 2026)—— "呈现质量"独立于"检索质量"
* 四个阶段(**每个都可独立替换**):
  ①**切段**:主题连贯窗口 **3~10 轮**,相邻轮 embedding 余弦低于阈值即下边界;
  ②**双索引**:dense(mean-pooled **BGE-M3**,1024 维)+ **稀疏 BM25**;
  ③**检索**:BGE-M3 编码查询 → dense 余弦 + BM25 → **RRF Σ1/(60+rank)** →
    **时间加成 +0.10**(查询含时间词,匹配"昨天 / 上周 / ago / since"类模式表)+ **实体加成 +0.05/实体** →
    **交叉编码器 ms-marco-MiniLM-L-6-v2 重排 top-50 → top-k**(LoCoMo k=10、LongMemEval k=15,dev 选定);
  ④**证据高亮**:交叉编码器给**段内每一行**打分,把最高分行作为 `Evidence: <best line>` 附上 ⇒ 对抗 **"lost in the middle"**;
* **"bounded by design"**:存储**显式封顶** —— **去重**(与已存段余弦 ≥ τ 即丢弃)+ **预算上限 B=400 段、FIFO 淘汰最旧**;
  切段本身把存储压缩 **4~5×**(相对轮次级);
* **低置信度过滤**:取回段的最大余弦相似度低于阈值 ⇒ **抑制结果**,防止弱相关上下文误导模型
  ⇒ **与 MemX 的拒绝闸同一机制,第二个独立来源**;
* 核心命题(**H4 presentation-quality isolation**):若"平面检索"与"完整 CPP"的 **Recall@k 完全相同**
  而答案正确率不同 ⇒ 增益是**呈现驱动**而非检索驱动;摘要已给答案:**有界 CPP 的会话级检索指标与无界基线相当**
  (LoCoMo 相同、LongMemEval 略低),**但答对的题更多**;
* 它引用的前置结论:按主题分段的 **3~10 轮段**稳定优于轮次级与会话级;**BM25+dense 混合比纯 dense 召回高 15~30%**;
  交叉编码器重排是 RAG 的高收益升级 —— **三条它都当"第一等架构决定"收进来**;
* 基准构成:**~40 会话 / ~115K token;single-session 150、multi-session 121、temporal 127、knowledge-update 72、
  abstention 30**(注意:**它单列了"拒答"一类**)。

### 12.3 第六轮结论
1. **N4 / N5 有现成机制**:TRACE = **层级图 + 有类型演化边(update / contradiction)+ 有效性标注 +
   更新感知种子扩展**;其消融把病根写成"**取回更旧但词法更相似的一版**",解药是**沿演化边扩展**(不必换检索器);
2. **"拒答 / 低置信抑制"现在有三处独立来源**(MemX 规则、CPP 低置信过滤、CPP 单列 abstention 类别)
   ⇒ 把它排在第一位是有依据的;
3. **呈现是独立变量**(CPP H4):**同为 Recall@k,把"最相关的行"显式标出来**答案还能不同 ⇒
   我们量台现在只有"覆盖",**既不量顺序、也不量呈现** ⇒ 修尺子清单再加一项(**呈现 / 位置敏感性**);
4. **"bounded by design"**(显式上限 + FIFO + 去重)与我们已加的 30 天剪枝同向:上限是**设计约束**,不是事后清理。

### 12.4 优先级(第六次更新)
1. **量台升级**:顺序敏感(MRR / NDCG@5)+ 白盒支撑(SEH@3 / SRS)+ 干扰项 + 失败分解(检索 vs 利用)
   + **呈现敏感性** ——
   ✅ **2026-09-30 已落地前一半**(顺序敏感 + SEH@3 + 失败分解 + 装下k;
   负控 `IDENTICAL`,见 `RETRIEVAL_BASELINE.md` §6)。剩下三项(干扰项 / 呈现 / 利用失败)

   **生产改动待他批准**;
3. **演化图 / 有效性标注**(TRACE:update + contradiction 边 + 更新感知扩展)—— **直打 N4 / N5**;
4. **迭代检索**;
5. **多粒度 + 熵路由**;
6. **结构化索引族 + 事件日历 / 双时间**;
7. **呈现层**(CPP 式"每段高亮最相关一行")—— 若量台能量出它,**可能比换检索器更便宜**;

### 13.2 幻觉与冲突(评测的"上游"面)

### 13.3 图作为"动态记忆对象"+ 迭代检索(三篇同族)
* **SAGE(2605.12061)** —— `Self-evolving Agentic Graph-memory Engine`
  * 立论:"现有 RAG/GraphRAG 把记忆图当**静态检索中间件**" ⇒ SAGE 把图当**动态长期记忆对象**,
    **Writer**(策略式写入 + reader-aware 写入奖励)与 **Reader**(图基础模型)互相**自演化**;
  * Reader 侧四件:认知启发的**结构化查询规划**、**软寻址与记忆片段预激活**、
    **突触式结构条件传播**、目标图校准与跨图结构先验;
  * ⇒ 喂我们:**③演化图** + **④迭代检索**;
* **HERO(2608.22310)** —— `Human-profile Enhanced Retrieval Optimization`
  * 异构记忆图(**忠实保留原始对话**,不做 LLM 重写 ⇒ 明确反对"摘要式有损压缩");
    Episodic Layer(Traces→Units→Cues)+ Profile Layer(Profile Insights→Cues);
  * 检索:实体匹配 cue 节点得初集 → **迭代 cue 激活**(经 Cue–Unit / Cue–Profile 桥)→ 喂 **Personalized PageRank** 初始化;
    两个维度分开:**查询相关性** vs **隐式推理(画像一致性)**;
  * 数字(已核,正文原句):**LoCoMo F1 56.06%**、**PERSONAMEM 准确率 70.63%**;
  * ⇒ 喂我们:**④迭代检索 + 画像层**(我们的 N6 偏好档没有任何专门的表示);
* **EAR(2607.17879)** —— `Exploratory and Assimilating Reflection`
  * 结构:**查询内**迭代深搜(Explorer)造上下文 → 训练自适应重排器;**跨查询**用 Experience Buffer 做**经验回放**;

  * ⇒ 喂我们:**④迭代检索**——它同时给了"不用 RL、用回放"的省样本路径。
