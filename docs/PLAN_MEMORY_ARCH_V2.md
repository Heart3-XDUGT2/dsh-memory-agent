## §2 设计原则(16 份材料的六条共识 → 本方案的硬约束)

1. **联想在查询期算,不在盘上铺概念↔概念的两两边。** ⇒ A4/A6 的形态选择。
2. **分组一律"算出来",且允许多归属。** ⇒ A5 用软聚类 + 摘要,不写分类本体。
3. **"换代/失效"只在矛盾时发生。** ⇒ A1 只在**显式声明的单值关系**上换代。
4. **变乱的根因是"没有类型 + 粒度不齐"。** ⇒ A2(谓词归一)+ A3(`kind`/`evidence` 必填)。
5. **检索分 = 近因 + 重要 + 相关;遗忘 = 衰减 + 复述强化。** ⇒ 我们已有的 `activation/half_life/intrinsic_value/recall_count` 不动,只给它们**新的候选来源**。
6. **记忆是分层组件,图只是其中一层。** ⇒ 本方案不把联想责任全压给图谱;情景(记忆)/语义(边)/主题(簇)各司其职。

## §3 目标架构(五层 + 数据流)

```
L0 情景层   episodic_memory 一行 = 一条记忆 = 一条「n 元事实」(超边载体,summary 就是那句自然语言描述)
L1 语义层   graph_nodes(概念,经 graph_aliases 归一) + graph_edges(有 kind/evidence/基数的**事实**边)
L2 证据层   graph_cooc_evidence(哪条记忆里同时出现了哪些概念)          ← 影子表降级到这里
L3 主题层   graph_topic_clusters + graph_topic_members(软聚类 + 每簇摘要)= 他要的"喜好"层(可重算视图)
L4 检索层   ①字面/种子(既有) ②图邻居(既有 graph_activate) ③只读 PPR + 时间邻近缓冲(新,报表优先)
```

**数据流(写入侧)**:记忆落库 → Judge 抽概念/关系 → `graph.py.add_edge`(基数闸 → 归一闸 → 类型闸)
→ 事实边;**共现**走 `graph_mine` → 裁决 → **证据表**(不再落 pair 边)。
**数据流(读取侧)**:既有读口(`load/top_nodes/graph_activate/render_paths`)**逐位不变**;
新读口(PPR/簇)**只读、只报表**,要进 prompt 得**另立一次他的裁决**(红线:人格注入点)。

**与现状的差异**:①换代判据从"槽唯一"改成"基数 + 矛盾";②谓词归一;③边有类型;④共现不落边;
⑤多一层**可重算**的主题视图;⑥检索多一条只读通道(默认关)。
