┌──────────────────── DSH 侧(dsh-echo 插件 = 核心)────────────────────┐
│ 桥:幂等 → 找/建/续**陪伴会话** → 场合正文前缀 → followup             │
│ 陪伴会话:人格注入 · 记忆检索 · 图谱 BFS · 想念/情绪/钟面 · 工具        │

### 1.2 反向流:她先开口(最容易漏的一条)

心跳**不是**新起一个调度器:它已经挂在每个 root agent 上、60 秒一跳
(`lib/index.js:1239-1267` → `heartbeat.tick(agent)`),想念三重闸门与提醒扫描都在引擎侧
(`lib/heartbeat.js:188-245`)。所以:

> **桥必须在启动时就把陪伴会话 resume 起来并保持存活** —— 否则没有 root agent,
> 心跳不跑,她**永远不会主动说话**。这是「主动开口」在架构上唯一的新要求。

`capture.proactive` 这个标记现成(`lib/index.js:920`)⇒ 出站时能区分
`kind:'proactive'` 与 `kind:'reply'`,平台侧可以分别对待(比如群里只回不主动)。

## 2. 边界判定:什么进 DSH,什么留 A

**三条判据**(拿它过一遍每个模块,别凭感觉):

- **判据①** 是否写「她是谁」的状态(记忆 / 图谱 / 情绪 / 画像 / 想念 / 议程 / 审计)
  → **必须 DSH**。写两份 = 迟早两套说法(这正是「对不上」的病根)。
- **判据②** 是否需要平台凭据、平台协议、平台限频、平台特有的 ID 概念
  → **必须 A**。
- **判据③** 两条都沾 → **拆**:数据面(说了什么、记住了什么)在 DSH,
  传输面(字节怎么送出去)在 A。

#### 3.2.1 投递纪律:与心跳同一把锁(别自己造一个)

零件已经在跑:`lib/heartbeat.js:154-168` 用
`agent.runMaintenance(() => agent.followup(createUserMessage(...)))` 投递主动话 ——
**认领空闲维护相,忙就拿不到锁、下一分钟再试**。入站注入必须走**同一把锁**,否则
QQ 消息可能插进她正在跑的那一轮里(工具调用中途),那是脏上下文。

由此定下桥的忙语义:

- 拿不到锁 ⇒ 入站**返回 `503 {reason:'agent-unavailable'}`**,
  **不丢消息也不 ack**:适配器按 `msgId` 重试(入站幂等已经保证「重试不会让她答两遍」)。
- 适配器侧退避要**有上限**并写日志:她长时间忙(比如在跑一个长任务)时,
  QQ 那侧最多等 N 次,之后回一条「她现在忙着」的兜底话术(而不是静默)。

## 8. 与今天的记忆修理的关系(为什么顺序是对的)

   而不是先碎再合。别名表 + 合并脚本是 R1 现成的零件。

   而且合并会把「同一件事的两种说法」当成两条新记忆灌进来 —— 现在有闸挡着。
4. **画像(M4)让「她以为我是谁」有唯一答案**:QQ 侧画的像(`__shared__`, affinity 88)
