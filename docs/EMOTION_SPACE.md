# 情绪空间融合(EMOTION SPACE)—— 联合空间、桥接与影子渲染

> 第三批(2026-10-05)落地。设计裁决全文见桌面的
> `情绪架构融合设计-2026-10-05.md`;本文是**实现侧**的说明书:
> 每一处 [工程假设] 写在哪一行、怎么调、怎么回滚、怎么验。
>
> **一句话结论**:情感二维系(P×A)与人际环形模型(IPC)之间,**文献只支持
> 共享一条轴**;其余都是本仓的工程构造。因此本仓**不声明**"两套坐标是同一个
> 空间的两个投影",也不提供双向精确互推;我们做的是
> **「联合空间 + 一条文献共享轴 + 显式标注的桥接 + 影子优先的渲染」**。

---

## 1. 为什么不能做"同一空间"

| 证据 | 内容 | 后果 |
|---|---|---|
| Yik & Russell 2004(*MBR* 39(2):203–230) | 两个环形模型实测只重叠**一条轴**:情感环侧 35°、IPC 侧 71°(N=395) | 只能有一条共享轴;垂直轴无依据 |
| Yik 2010(复现) | 37° / 76° | 那两个角不是抽样偶然 |
| Mehrabian 1995(*J Psychol* 129(5):565–581) | 公共因子需要**三个**(pleasantness / dominance / arousability) | 3 维 vs 2 维 ⇒ **双射在维数上就不可能** |
| Mehrabian 1996(*AJP* 48(2):86–92) | 正向 5 条 / 反向 3 条 OLS,**不是代数互逆** | 反向换算只能是估计,必须标误差 |
| McCrae & Costa 1989(*JPSP* 56:586–595) | IPC 平面更接近 E × A,不是 P×D | 再一条"别当同一空间"的旁证 |
| Russell 1980 | 情感环本身是 P×A 二维,`D` 是 PAD 才有的第三因子 | `dominance` 只登记、不渲染 |

**所以**:任何"两套坐标合成一个总分"或"用一段回推另一段"的写法都是编数据。
渲染层的三条禁令就是这条结论的落地(见 §4)。

## 2. 联合空间怎么定义(`lib/emotion-space.js`)

基是三维 **双极 [−1, 1]**,原点 0:

| 轴 | 含义 | 来源 |
|---|---|---|
| `s` | 共享轴:情感环与 IPC 实测共享的那条斜轴 | **[文献]** Yik & Russell 2004(35° / 71°) |
| `a` | 激活轴:与共享轴正交的唤醒方向;IPC 侧无对应 | **[工程假设]** 取正交补 |
| `d` | 支配轴:同名(dominance / DOM)但**异刻度** | **[工程假设]** |

三个子空间各自保留原生量纲,互不换算:

| 子空间 | 原生 | 单位 | 原点 |
|---|---|---|---|
| `SP_PAD` 情感 | `valence`(−10..10)、`arousal`(1..10)、`dominance`(0..10,登记未渲染) | 原值 | 心情 0 / 唤醒 3 / 支配 5 |
| `SP_IPC` 人际 | IPC 的 `a`(掌控/agency)、`c`(联结/communion),加 `playfulness`/`sadness` 两个**扩展维** | 单极 0..1 | 0.5 / 0.5 |
| `SP_IND` 独立 | `fatigue`、`longing.value`、`user_profile.affinity` | 原值 | 各自 | 

`fatigue`(疲惫)**没有** PAD 对应维 —— 它在 PAD 里常被误当成"低唤醒",
但本仓不这么算:它归独立空间,不参与任何旋转。

## 3. 桥接层怎么算(`lib/space-bridge.js`)

```
PAD ──旋转(θs)──▶ {s, a}         IPC ──旋转(θs_ipc)──▶ {s}
        └──支配轴耦合(θd)──▶ d          └──尺度(λd)──▶ d
```

- **共享轴**:`s = cosθ·P + sinθ·A`(情感侧 θs=35°);IPC 侧把单极 `a/c` 折成
  双极后同样旋转(θs_ipc=71°)。
- **支配轴**:`d = λd·G + sinθd·s`(θd 默认 0 ⇒ 两侧各自独立)。
- **往返**:情感侧是正交旋转 ⇒ **无损**(误差 ≈ 1e-6,来自坐标取整);
  IPC 侧要回原坐标必须**读缓存**(旋转后的第二分量)—— 缓存缺了就标
  `degraded`,走投影近似,**绝不假装成功**。
- **误差只记账、不回写**:`compareShared()` 只算 `bridge_err = s_ipc − (λs·s_pad + biasS)`
  与残差统计;`snapshot()` 里能读到 `sharedErrN / MeanAbs / MaxAbs / Last`、
  `rtPadMaxErr / rtIpcMaxErr`。**没有任何一条路径会把误差写回任何一维读数。**

## 4. 渲染层(`lib/context.js` 的 `renderUnionBlock`)

**B5(2026-10-05)按审阅报告收过一遍**:块从 5 行 463 字压到 **2 行**(降级时 3 行),
`bridge_err` 不再进 prompt,歧义点清零。现格式:

```
- 情绪空间:共享轴 s=…(情感环与 IPC 的实测公共方向 [文献]);两套坐标系不等价、不可互推,别相加、别互推。
- 分段:[PAD] 愉快 …、激活 …、支配(未启用);[IPC] 主导 …、亲近 …、最近姿态「不夸大(BC 一带)」 —— 该值来自另一套坐标系,**不与上段比较**;[独立] 疲惫 …(无 PAD 对应维)。
```

七条修正(对应审阅 §一):①`bridge_err` 只进审计;②**拿不到的字段一个字都不写**
(照 `dimLine` 的缺维纪律;根因是 `Number(null) === 0` 会把"没有读数"渲染成 `0.00`,已被 `num()` 严格化);
③IPC 段加限定句"不与上段比较";④联合行只留共享轴 `s`(`a`/`d` 归各自段,不再重复);
⑤姿态带分仪名;⑥尾句句号;⑦支配标 `(未启用)`。

### 门禁(绿 / 黄 / 红;只读判定)

每次渲染前算**当前参数下**的残差 `resid = s_ipc − (λs·s_pad + biasS)`,由 `gateOf(resid)`
分带(`lib/space-bridge.js` 的 `GATE_BANDS`):

| 带 | 阈值 | 行为 |
|---|---|---|
| 绿 | `\|resid\| < 0.15` | 正常给块(2 行) |
| 黄 | `0.15 ≤ \|resid\| ≤ 0.30` | **只给方向**(“相对上一轮偏正向”),不给任何绝对读数 |
| 红 / 未知 | `> 0.30`,或残差拿不到 | **不给块**(返回空串),只写审计 |

- **为什么挂在残差上而不是原始差**:一改 `biasS` 阈值就失效 —— 同一批 7 轮数据在
  `biasS=0` 时全红黄、在 `biasS=0.30` 时全绿;挂在残差上阈值才稳。
- **门禁是只读的**:它只决定"这块给不给模型看",**绝不回写任何读数**(与"误差只记账"同一条纪律)。
- 块的位置在「剧本」之后、「行为要求」之前(`describeMood` 的 `opts.unionBlock`);
  影子模式(`bridgeShadowMode=true`)下调用方**根本不构建**这个块。

## 5c. 语气候选:情绪读数 → `<emo>` 候选(方案 C,2026-10-05 ① + ②)

**要解决的问题**:heart-tts 的行内语气标签 `<emo type="N">…</emo>`(「这句话怎么念」)此前与情绪架构
**零耦合** —— 教学只靠它注册的运行时 skill,模型自己临场挑号。这一节是融合的落地记录;
盘点(含两边的映射可能性与 A/B/C 三方案取舍)见
`交接档 emo融合盘点-2026-10-05.md`。

### 设计:**触发量是 `delta`,不是绝对强度**

- `<emo>` 的正确用法是"**情绪有转折**、要强调、要压低声音的那一句"(它的 skill 原话:
  「一句话一个标记就够了;每句都标反而听起来平」「不确定就不加」)。
- 情绪空间恰好给了"上一轮 → 这一轮"的变化(`moodIntensity` vs `prevMoodIntensity`)。
  拿**绝对强度**当触发量,语气会每轮都飘;拿**变化**当触发量,不出行就是常态。
- 所以:① `delta = 0`、② 读不出变化、③ 候选被掏空 ⇒ **一个字段都不进 prompt**。

### 职责边界(与「行为要求」那行不重复)

| 行 | 管什么 | 落在哪 |
|---|---|---|
| 行为要求(`lib/context.js:251`) | **话怎么写**:句长、用词、要不要挑起话题、安静不等于变冷 | **文本** |
| 语气候选(`lib/style-hint.js`) | **话怎么念**:`<emo type="N">` 候选 | **TTS 朗读** |

一行改文本、一行改韵律,不重叠;语气候选文案里写明 `(朗读用)` 免得模型拿"语气"一词
把两件事搅在一起。**行为要求不动。**

### 参数([工程假设],只有一处口径)

全部在 `lib/style-hint.js` 文件头与函数里(`describeMood` 与宿主都不重复判断):

- 唤醒度三档:`arousal ∈ 0~10` ⇒ `≤3 偏低 / 4~6 居中 / ≥7 偏高`;
  **读不到 ⇒ `unknown`,不再假装居中**;
- 心情符号:`valence < 0` 记负、`≥ 0` 记正;读不到且**门禁绿** ⇒ 用共享轴 `s` 的符号兜底

  `1` 是"没转折",都不由情绪推;
- 文案长度:最短 56 字、最长 **101 字**、平均 83(`LINE_MAX = 101`,电池里断言)。
  (2026-10-07 换 XML 语法后重测:旧方括号写法时是 49 / 80 / 69。变长的只有**写法** ——
  一个标记从 `[emo:2]` 的 7 字变成 `<emo type="2">` 的 14 字,一行最多三个 ⇒ 恰好 +21;
  信息一个字没加,所以上限跟着格式走。)
- 出行比例:192 格里 72 格出行(其余 120 格按 delta=0 / 读不出变化 / 候选被掏空不出行)。

### 门禁降级矩阵(4 门禁 × 4 唤醒 × 3 心情 × 4 delta = 192 格)

规则:**门禁只决定"能不能引用共享轴 `s`"**(`sTrusted = gate === 'green'`),
不决定出不出行;真正"什么都不该说"的是**自身读数也缺**。

| 情形 | 候选 | 出行? |
|---|---|---|
| 唤醒 ↑ + 心情正 / 缺 | `[2]` 上扬 | ✅ |
| 唤醒 ↑ + 心情负 | `[5]` 紧张 | ✅ |
| 唤醒 → + 心情负 | `[4]` 低沉 | ✅ |
| 唤醒 → + 心情正 / 缺 | `[2]` 上扬 | ✅ |
| 唤醒 ↓ + 心情负 | `[4]` 低沉 | ✅ |
| 唤醒 ↓ + 心情正 = **平静** | 空 | ❌ 默认语气就是对的 |
| 唤醒缺 + 心情正/负 | `[2]` / `[4]`(文案不提唤醒) | ✅ |
| **自身读数全缺**(唤醒与心情都没读到) | 空 | ❌ **任何门禁都不出行**(含绿带:共享轴单独一条不足以挑语气 —— 两套坐标"不等价、不可互推") |
| `delta = 0` 或读不出 | — | ❌ |

黄/红/未知时 `s` 一概不引用,候选只从她自身的读数推;门禁尾巴只留一句 `(按体感)`
(绿灯什么都不加 —— 那是默认情形)。192 格里 **74 格出行 / 118 格不出行**
(绿带比黄/红多 2 格:心情缺时 `s` 能兜底)。

### 开关与回滚

- 开关:`settings.styleHint`(**默认 `true`**),面板「调参 → 情绪空间融合」里一格;
  面板页「情绪空间」第四张卡把这一行显示出来(含候选/禁区/触发/门禁/来源)。
- **回滚**:置 `false` ⇒ `describeMood` 少一行,**与加这个功能之前逐字节一致**
  (实测:399 字 → 473 字,差的 74 字就是它)。
- 融合侧**不维护样式表**(不拉 `GET /characters`、不缓存、不校验):权威表在 heart-tts 侧,
  这一层只出**号**;`STYLE_LABEL` 只是显示用读法,表里没收录的号就只给号。
- 不碰:heart-tts 本体、TTS 服务、`lib/relay.js`、`voice-receipts`、记忆架构。

## 5d. 用户侧坐标(轮末异步)+ 人格基线 + 锚点清单删除(2026-10-06)

**来源**:设计文档《情绪面板缺口补齐设计-2026-10-06.md》(桌面《交接》),他拍板九项。
本次落地 **MVP-1(库 + 端点)/ MVP-2(人格基线)/ MVP-4(护栏 + 测试)+ 锚点删除**;
**MVP-3(前端)明确留到演示之后** —— 所以面板现在**一点都没变**。

### ① 同源路线:双轨 + 对账(**甲案**)

| 谁的坐标 | 怎么来 |
|---|---|
| **她**(`ipc.role`) | 老路不变:`emotion_vector` → `echoToIpc` 映射(`爱意→联结`、`依赖→(1−掌控)`) |
| **他**(`ipc.other`) | **轮末异步**用 `lib/ipc-core/appraise.js` 的**上游提示词**直判(不新写提示词),结果并进 `emotion_vector` 的 `ipc_dyad` 键 |

同一次判定里模型同时给出 `self`(她眼里的自己)与 `other`(她眼里的他):
`self` **不用来改任何坐标**,只与"映射出来的她"做**残差** `ipc_err` ——
**只记账、不回写**(也**不进** `space-bridge` 的 `s` / 门禁:那是联合空间自己的残差,
别混)。分带阈值直接复用 `space-bridge` 的 `GATE_BANDS`(`0.15` / `0.3`)⇒
`green` / `yellow` / `red` / `unknown`。**红档不画数**(`other` 与 `metrics` 都不给,
面板照旧灰环)。阈值标定等到 ≥30 轮真实数据之后再做。

### ② 编排纪律(拍板 ②③④⑤⑥ + §5 风险 3)

- **打分跑在主包**(QQ 侧一行不动);**不进 prompt**(一期只上屏),**不占回复时延**;
- **节流两道闸**:每 3 轮 **且** 间隔 10 分钟(参数都在调参面板:共 5 项);
- **串在反思之后**(不是并行):两条路都会写 `emotion_vector`,并行会让后写的把对方的键抹掉;
- **可信度门槛**:`gain = 模型自报把握 × 解析完整度(不完整打对折)`,低于 `0.35`
  **不落库**,只写审计;
- **不许静默**:总闸关 / 节流 / ipc-core 不可用 / 通道没产出 / 可信度不足,**五种都留痕**
  (审计一行 `toolCall: 'ipc-appraise'`,状态面 `echo_status.ipcAppraise` 计数 + 原因);
- **零 DDL**:只往 `emotion_vector`(TEXT JSON)加 `ipc_dyad` 键 —— `agent_state` 是
  JS/PY 共有表,加列要镜像改 `python/engine/db.py`,一期不加。

### ③ 人格基线(拍板 ⑦⑧)

- 只做 **P/A 两维**,`d` **恒 `null`**(支配维"已登记未启用",基线不许把第三维编出来);
- 口径是**原生值**(同 `global.valence` −10..10 / `global.arousal` 1..10),
  **不经联合空间桥接**;要上立方体时由 `lib/her-baseline.js` 的 `baselineUnit()` 现算双极坐标;
- 存 `config.json`(`herBaselineEnabled/P/A/Source/UpdatedAt`,共 5 项面板字段),
  **不入向量、不入库表、不动 persona.json**;
- 没开总闸 / 没填 ⇒ 端点顶层 `baseline: null` ⇒ 面板整块跳过(**不画一个没人填过的点**)。
- 模块另给了 `baselineFromMean()`(用最近 N 轮的 P/A 均值当基线,`source:'mean'`)——
  **本期只备函数,没有面板按钮**(等前端一起做)。

### ④ 锚点清单删除(拍板 ⑨)

端点的 `ipc.anchors` **改成恒 `null`**(33 条单方姿态目录与 `region.label` 功能重复,
且不随读数变化);**`lib/ipc-core/lexicon.js` 模块保留** —— `describeRegion` 的最近词、
178 条关系状态词、注入侧取姿态词都靠它。砍的是"目录展示",不是词表。
