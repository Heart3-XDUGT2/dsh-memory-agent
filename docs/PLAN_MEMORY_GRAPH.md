## 1. 问题陈述

我们的图谱现在是一个**几乎不携带结构的星形图**：28 个节点全部是 `concept`（`belief` 0 个），42 条边里 23 条活跃，而 `is_protected=1` 的节点 **0 个**；度数最高的是 `用户`=20，其余只有 `校园跑` 3、`Echo` 3，**度为 0 的节点有 8 个**，**不含 `用户` 节点的活跃边 ≤2 条**。也就是说，几乎所有边都从 `用户` 这一个中心射出，节点之间（尤其 `用户`/`<称呼>`/`她`/`助手`/`Echo` 五个人格节点之间）**互相无边**。检索侧又"只认边"：`load(conn, owner_key)`（`python/engine/graph.py:423-442`）只加载被本人边引用到的节点，孤立节点在检索里不可见，清理逻辑（`graph.py:965-972`）还会删掉无任何边的节点 —— 于是**扩散在现状下等于没启用**：能游走的路网几乎只有一根星形辐条，走不出一跳。（注：**不是没有扩散代码** —— `graph_activate` 的 best-first 激活早已存在，问题是**没有路网可走**；且节点 `activation` 列从不被写、恒为 0。更糟的是，既有工单已查明**连种子都是废的**：`FIX_PLAN.md:33-46` 记"**BFS 每轮 0 条**"，三条种子通道全废（字面命中 / `extraSeeds` 从未接上 / 机械切分），反证是"输入里带实体名时 BFS 出 8 条" ⇒ 本计划第三期**必须先修种子**，不能假设"路网建好就有效"。详见 §3.5。）这不是"边太少"的问题，而是**边的产生机制被结构性地锁死了**（成因三层见 §3）：提取器的语义锚要求"关系 = 用户确立的事实"（`python/engine/judge.py:603`、`python/engine/l0_tier.py:60`）；槽位 `slot = source_id || '|' || relation`（`python/engine/db.py:14`）让同一"主语+关系"只保留一条活跃边，新宾语顶掉旧宾语（`graph.py:404-410`），**结构上禁止扇出**；节点保护只对 `node_type='person'` 生效（`graph.py:411-419`），而 `get_or_create_node`（`graph.py:220-248`）从不写 `node_type`，**保护恒不生效**（与"28 个全 concept、`is_protected=0`"吻合）。因此"多建 LLM 边"不是答案：它既绕不开槽位约束，又要把最贵、最不稳的一环（LLM 判定）压在图的主路径上 —— 而实测告诉我们，记忆与图是**两套互不相通的存储**（`episodic_memory` 活跃 217 条，其中提到 ≥1 个已知节点的 191 条、提到 ≥2 个的 **85 条**），**这些共现关系已经躺在记忆里、"白送"了，只是从没被写成边**。（注：v0.16.0 的 M1 已给边加 `evidence` 回指、实测 18/33 有依据 ⇒ "两表互不相通"这句**已被部分修掉**；口径见 §3.5。）

关键数字一览（现状实测）：节点 28（concept 28 / belief 0）· 边 42（活跃 23）· `is_protected=1` 0 · 度最高 `用户` 20 · 度 0 节点 8 · 不含用户节点的活跃边 ≤2 · `episodic_memory` 活跃 217（≥1 节点 191 / ≥2 节点 **85**）· 时间边候选 216 · 共现边（同记忆）30 → 去说话人后 **5** · 共现边（同天）94 → 去噪后 **42**。

## 2. 第一性结论（选型）

### 2.1 记忆分几层，我们缺哪层

按调研（`research-edges.md` 汇总表 + 三句话结论），业界记忆大体分这几层，并对应两种"关联"承载方式：

| 层 | 承载什么 | 关联怎么来 | 我们是否已有 |
|---|---|---|---|
| 情景层（episodic） | 一条条原始经历 / 观测，带时间戳 | 时间戳绑定、时间相邻 | **有存储**（`episodic_memory` 217 条），**但没进图**（缺） |
| 语义层（semantic / concept） | 去时间的事实与概念 | 共现、抽取 | 有（28 个 concept 节点），**但它就是星形的中心** |
| 关联层（associative） | 把上面两层连起来的"结缔组织" | 边本身 | **缺**（图里只有星形辐条） |
| 程序层 / 工作层 / 画像层 | 技能、当前上下文、用户画像 | 分层 / 分页 / 打分（多数系统**故意不建边**） | 与本计划无关，不动 |

结论：**我们缺的不是"语义层"，而是"关联层"与"把情景层接进图"的动作**。MemGPT / MemoryOS / Generative Agents 证明"不建边也能跑"（用 70%/100% 双阈值 + FIFO 递归摘要，或 0.995 衰减打分），但那只解决"该想起哪条"，**不解决多跳**；AriGraph 与 StructMem 给出的是更便宜的路：**把时间戳当边用**（AriGraph 情景超边"happened at the same time"；StructMem 同 τ 绑定 + 周期性合并）。所以缺的那层，**应该用"几乎免费的边"来补，而不是用 LLM 抽三元组来补**。

> 既有评测侧还给了两条同向的官方数字（`MEMORY_EVAL_PROTOCOL.md` §4，**是 LongMemEval 的实验读数，不是我们的**）：**value 粒度按会话切分 ⇒ +11.3% recall（以"轮"为值）/ +6.8%（以"会话"为值）；key 扩展（用抽出的用户事实做键）⇒ +9.4% recall@k / +5.4% 准确率**。前者直接支持"给情景层一个更粗/更细的粒度"，后者与本计划"把已有记忆里的东西变成可检索结构"同向。

### 2.2 边的分类：每类由什么触发、代价多少

| 类 | 触发机制 | 代价 | 代表 | 风险 |
|---|---|---|---|---|
| ① LLM 判定 | 抽取 / 判"是否相关" / 判失效 | **最贵最不稳** | A-MEM（向量 top-k 预筛 + LLM 精判）、AriGraph（三元组抽取 + outdated 检测）、StructMem（合并期合成关系假说）、Mem0^g | 原文承认"幻觉关系会变成 **persistent structural noise**"；Mem0 图版建图 **35.825M tokens / 53514 calls**，LoCoMo 只得 **68.44** |
| ② 共现统计 | 同一记忆 / 同一分段内同时出现 | **最便宜，但有歧义** | HyperSU（MDL 分段共现，**0 indexing token**）、AriGraph 语义边 | 会把说话人节点灌成噪声边（我们实测：同记忆共现去说话人后只剩 **5** 条） |
| ③ 时间相邻 | 相邻记忆 / 同一时间戳 | **几乎免费，但有损**（同刻 ≠ 相关） | AriGraph 情景超边、StructMem 时间绑定 | 只给"顺序"，不给"语义" |
| ④ 层级归属 | 把节点归到某个 tier / 社区 / 摘要 | **免建边，但丢跨层关联** | MemGPT、MemoryOS、Generative Agents 的 reflection 层 | 跨层多跳无符号路径 |
| ⑤ 故意不建边 | 用分层 / 分页 / 摘要 / 打分扛"关联" | **零结构成本** | MemGPT、MemoryOS、Generative Agents | 多跳全靠检索现场重建 |

**选定的边策略**：主用 **③时间相邻 + ②共现统计**（两者都在我们已有数据里"白送"）；①只允许出现在**离线、可回滚、非主路径**的位置，且默认关。

### 2.3 扩散用哪一族算法，哪些组件承重

族谱三条路（`research-spread.md` §7、§8）：

1. **单步静态图扩散 = PPR**（HippoRAG / HippoRAG 2）：离线建一次图，在线一次随机游走完成多跳，**纯图计算、零在线 LLM**。成本 ≈ **$0.1 / 1000 queries**，单步检索 **0.255s**（比 LightRAG 快 3–5×、比 GraphRAG 快 8–11×）。消融证明：**PPR 不能退化为"只用种子"**（R@2 57.4→50.7），"种子+邻居"更差（→42.2）⇒ **要的是收敛的 PPR**；**抽取质量最承重**（换成 REBEL 掉 11 点）；同义边≈1 点。
2. **多轮认知动力学 = Synapse 式**：双层图 + 双触发锚点 + **fan 稀释（除以出度）** + top-M 侧抑制 + sigmoid，3 轮。在线零 LLM，814 tok / 1.9s / $0.24 per 1k。消融结论 **"dynamics, not topology, do the heavy lifting"**：去 Node Decay → Temporal **50.1→14.2**；去 Fan Effect → open **25.9→16.8**、多跳 **35.7→30.2**；去侧抑制 → **39.4**；去门控 → 对抗 **96.6→67.2**；Vectors Only → **25.2**。
3. **不是扩散的边路**：GraphRAG（Leiden 社区 + 摘要 + map-reduce，**索引 115.5M tokens / 277 min**，QA 每查询 10.7s，**无 local 能力**）与 LightRAG（双层关键词匹配 + 1-hop，便宜但图方法里检索最弱：第三方复现 HotpotQA R@2 38.8 / MuSiQue 24.8 / 2Wiki 45.1）。

**承重件 / 装饰件判定**：
- **承重**：fan 稀释（对"一个 hub 连很多叶子"正是对症）、时间衰减（唯一管时序的件）、**Query→节点/三元组链接**（HippoRAG 2 里值 **12.5 点**，是最大功臣）、passage/情景节点（**6.1 点**）。
- **装饰 / 可省**：**在线 LLM 过滤三元组只值 0.7 点**（可省）；uncertainty gating 去掉只掉 0.2（40.5→40.3），主要买对抗鲁棒；侧抑制买去噪但**有反例**（见 §6）。
- **未知**：Synapse 的 **temporal/abstraction 边、dual-trigger、sigmoid 均未单独消融**；"Hub Explosion" 只有断言、**无实验**（`research-spread.md` §9）。
- **本仓已有的负结论（必须继承，见 §3.5）**：**RRF / 融合在本仓已三次被否**（同族打平、异族 = BM25、N5 单量 100→66.7），机制是"RRF 奖励各臂排名一致，而 N4/N5 要的是最新那条"；**图谱查询扩展在星形图上已实测零增益、16× 耗时**（旧文档据此搁置）。⇒ 本计划不再引入任何"再多投一票"的融合臂。

### 2.4 明确选定的五个原则

1. **动力学优先于拓扑**（引自 Synapse 消融原话 "dynamics, not topology, do the heavy lifting"）：先把"传播时怎么衰减、怎么按出度稀释、怎么归一化"做对，而不是先堆边。
2. **边只从"几乎免费"的来源来**：时间相邻（候选 **216** 条）+ 共现（同记忆 30→去噪 **5**；同天 94→去噪 **42**），两条都在已有 `episodic_memory` 里现成。**为它们付出的 LLM 调用目标是 0**。
3. **要花钱就花在"查询→节点链接"上，不花在"在线过滤三元组"上**：前者值 12.5 点、后者只值 0.7 点（HippoRAG 2 消融）。
4. **去噪是写入路径的常设闸门，不是一次性清理**（人类 2026-10-01 拍板，落法见 §4.5）：人工清一次会被新写入立刻回填（实测噪声占 **5/6**）；闸门必须**在写入那一刻**判（那时端点已知、判定零成本）。形状继承既有先例（`FIX_PLAN.md` F1/F10、`ARCHITECTURE.md:159-168`、`REFERENCE_ANALYSIS.md:280`），**不另开体系**。
5. **图谱不是只增不减 ⇒ 一切建边/搬边必须幂等、不记水位**：DMAE 每小时 `plan_prune` 删边 + 清孤点（`CORE_IN_DSH_PLAN.md:139-140`、`DB_MERGE_ANALYSIS.md:182`、`DEFENSE.md:137`）。去噪闸门、影子边与后续重测**一律"以当前库为准"**。

### 4.5 写入侧纪律：新建记忆与新边必须自动去噪（人类 2026-10-01 拍板）

> 原话：「你说要手动把这些噪音给它去掉，那么万一后面加了怎么办？**我们还需要加上一个，以后新建记忆必须要自动去噪**。」
> ⇒ 去噪从**一次性动作**升级为**写入路径的常设闸门**。
>
> **既有先例（本计划不发明新体系）**：写入侧"落地就校验/接地 + 不物理删"在本仓**已经发货** —— `FIX_PLAN.md:150-160` F1（写 `superseded_by` 前先 SELECT 校验）、`:252-270` F10（**关系别名归并 + 写入侧接地**，变体 `is_active=0` 下线、不物理删）、`:222-249` F8/F9（种子未命中返回空 + 跨会话噪声过滤）；记忆/画像落库另有 `ARCHITECTURE.md:159-168` 四层置信度门控（`<0.55` 拒收 / `0.55~0.75` 隔离 / `≥0.75` 落库）与 `REFERENCE_ANALYSIS.md:280`/`:300` 的 H1–H4"不过即拒"。**本节做的事只有两件：把这类闸门从"记忆/画像层"扩展到"图边层"，并把它从"跑一次的脚本"常设化为"写入路径的一部分"。**

**（1）为什么不能靠人工清理**

| 理由 | 证据 |
|---|---|
| 手工清一次，新写入立刻回填 | 共现实测：同记忆共现 30 条 → **去掉说话人节点后只剩 5 条** ⇒ 噪声占 **5/6**；写入侧不设闸门，每次反思都会用 `用户`/`Echo` 这类"人人都在场"的节点把边重新灌满 |
| 事后扫描天然滞后 | 清理只能在数据已脏之后跑；而**写边那一刻已经知道端点是谁**（判定零成本） |
| 本仓已有的先例都是"一次性清理" | `MEMORY_DEDUPE_REVIEW.md`（让位 25 行）与 `GRAPH_MERGE_REVIEW.md`（别名表）都是清一次；`RETRIEVAL_OPT_2026-09-30.md` §6.1 又证明"扩池类改动会把零重合记忆注成 `matched`" —— 同一类病会在写入侧复发 |

**（2）去噪清单（规则 + 违反时动作）**

| # | 规则 | 违反时的动作 | 依据 |
|---|---|---|---|

**（3）落点与时机**

- **必须在"写入那一刻"执行**（新记忆落库 / 新边落库的同一次事务路径内），**不是**检索时过滤、**也不是**事后扫描。
- 落点：**Python 侧唯一写边路径**（`python/engine/graph.py`）；**不新增第二个写入源**（`lib/` 侧不写图边，`graph.py:88`）。
- **默认关 = 零行为变化**：闸门自带开关，关掉时与现状逐位一致；规则表**纯增**，不改既有规则语义。
- **幂等 / 不记水位（C11）**：闸门与影子边一律"**以当前库为准**"，每次运行只依赖当前库状态；**不得**记"处理到哪了"的水位（DMAE 每小时 `plan_prune` 会删边 + 清孤点）。
- 失败必须**可见**（`DISCIPLINE.md` 规矩 2）：每次丢边/改边都留一行可查的痕 + `reason` 枚举，**禁止静默跳过**。

**（4）失败策略：丢边 / 改边 / 拒写入**

- **推荐：能改则改，不能改则丢边，绝不拒写入主流程。**
  - ① **主流程不能被图挂住**：写记忆/写边只是反思的副产物，拒写入会让"她记住这件事"失败，代价远大于多一条噪声边；
  - ② 既有先例：`graph-memory` 正是"**类型乱写就自动改，改不了就丢**"（`correctEdgeType()`），而不是拒绝整批；
  - ③ **丢边可恢复**（边可重算），**拒写入不可恢复**（记忆丢了）。
- 分层：R3 / R4（可自动改正）走**改**；R1 / R2 / R5 / R6 走**丢**；任何"丢"都要计数 + 留痕。
- **不做**：不因丢边回滚记忆写入；不因丢边抛异常中断本轮。

## 6. 风险与反例清单

1. **侧抑制会剪掉低度数叶子** —— Synapse 自己的失败案例：绿夹克 0.11 被 hub 0.85 压死；而**我们恰恰是低度数叶子最多**（度 0 节点 **8** 个、`校园跑`/`Echo` 各 3）。对策：β 取 **0.10–0.15**，或对单跳类查询**关闭抑制**（消融显示侧抑制主要买去噪，fan 与时间衰减才是承重件）。
2. **冷启动差** —— Synapse 自认；我们现状更极端（不含用户节点的活跃边 ≤2 条）。对策：第一期先只做测算，不承诺效果。
3. **说话人节点污染共现** —— 实测：同记忆共现 30 条，去掉说话人节点（`用户`/`<称呼>`/`她`/`Echo`/`助手`）后只剩 **5** 条。**必须硬排除**，否则边数虚高 6 倍且全是噪声。
4. **`is_protected` 恒 0** —— `graph.py:411-419` 只认 `node_type='person'`，而 `get_or_create_node`（`graph.py:220-248`）从不写 `node_type`。修保护必须先补 `node_type` 写入，否则保护逻辑永远是死代码。
5. **A-MEM 的两个坑** —— links 单向 + 下标对齐。抄近邻约束思路可以，抄结构不行。
6. **Graphiti 静默不失效** —— 无时间戳时不触发失效判定。我们要建时间边，就必须保证时间戳真的落库，否则"时间边"是假的。
7. **`node_type` 从未写入** —— 见第 4 条；这是"28 个全 concept"的直接原因，也是任何按类型分支的逻辑都不可信的原因。**第二期 b 必须显式写 `node_type='episode'`**，否则新增的 `episode` 节点同样会以 `concept` 落库、保护与类型分支继续失效（`ARCHITECTURE.md:183` 声称的"person 自动保护"则见 C5）。
    7b. **"改"与"纯增"的边界**：`get_or_create_node` 补写 `node_type` 属**行为改动**，不属纯增 ⇒ 必须默认关 + 可回滚；既有节点的 `node_type` 回填**范围与方式未定**（待确认）。
8. **孤立节点检索不可见 + 被清理** —— `graph.py:423-442` 与 `graph.py:965-972`。若共现/时间边只写不接读，节点仍会被清理路径删掉 ⇒ **第二期必须确认新增边能让节点免于清理**。
9. **槽位约束会吞掉新边** —— 若直接复用事实边路径，`slot = source_id || '|' || relation`（`db.py:14`）会按 `graph.py:404-410` 顶掉旧边 ⇒ 新边必须走**新的 kind 维度**，不能挤进原槽位。
10. **在线 LLM 迭代的反向证据** —— 见 §5；任何"再加一轮 LLM 精修"的提案都需先推翻这条。
11. **Hub Explosion 缺证据** —— Synapse 只在 Related Work 断言，**无实验**；不能拿它当"必须要侧抑制"的理由。
12. **"dynamics 才是承重件"也依赖未消融项** —— temporal/abstraction 边、dual-trigger、sigmoid 都**没有单独消融**，我们对它们的价值判断属于**推测，非实测**。
