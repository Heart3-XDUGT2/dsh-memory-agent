### 3.4 RT12 向量臂的技术门（✅ 已实测，`e0a1fe1`，内存库不碰真库）

| 门 | 读数 | 含义 |
|---|---|---|
| `node:sqlite` 加载扩展 | **只有 `new DatabaseSync(p, { allowExtension: true })` 能开门** | 其余两个名字一律 `disabled at database creation`。扩展是**每连接**加载 ⇒ 库文件不用重建，但 `lib/store.js` 与 Python 侧每处连接都要改 |
| FTS5 | 编译在里面（`ENABLE_FTS5`），但 **默认分词器对中文是瞎的**（`MATCH '相似'` → 0 行） | 现在的双语 BM25 **比 FTS5 默认更强** |
| FTS5 `tokenize='trigram'` | 「相似搜索」「数据库」命中，**「搜索」漏**（trigram 需 ≥3 字） | 中文二字词是主力 ⇒ 覆盖不全 |
| Python 侧 | `enable_load_extension` 可用、fts5 可用，但 **numpy 未装、sqlite-vec 未装** | 我们 python 现在是**零第三方依赖**（305 条裸跑），引入 = 引入本地二进制 |
| 模型运行时 | 本机**没有** ollama / sentence-transformers / openai key | "外部模型生成向量"这句在真机上是**空的** |

### 3.5 RT11 → RT13：向量臂三步走（**先量再上**）
1. **RT11 零依赖语义臂**：先做"同义词/别名臂"——用现成的 `graph_aliases` + 他手写的同义词表，
   接进 RRF 当**第三臂**。在金标上量：**N2/N3 涨不涨**。
   - 涨得动 ⇒ 说明缺的确实是"语义泛化"，向量臂值得付模型的代价；
   - 涨不动 ⇒ **向量臂不做**（省钱、省依赖、省 parity 风险），把结论写进文档。
2. **RT13 可选向量臂**（只有第 1 步的数据支持 + **他点头**才开工）：
   - 连接 `allowExtension: true` + 启动探测 `sqlite-vec` 在不在；**不在就自动降级**成今天的 BM25
     （复用 G3"降级要说话"的机制，她读得到 `[降级]` 标注）；
   - 向量 embedding **走本地 ollama**（不引云 API，私聊内容不出机器）；
   - 向量**只补召回、不比排**（RRF 加权），且**双端 parity**：Python 侧与 JS 侧必须同一模型 + 同一维度，
     否则金标会飘 —— 这一条是硬约束，做不到就不做。
3. **RT8（FTS5 / 同义词）裁决建议：不做 FTS5**。依据是 §3.4 的三条实测（默认分词器瞎、
   trigram 漏二字词、现有 BM25 已更强 + 双端对齐）。同义词那半条被 RT11 吸收。

**与第一轮 D 批的关系**：`D1 → RT10`、`D2（CrossEncoder 精排，动 Python 侧车）→ RT13 之后`、
`D3 画像候选池 / D4 时间三分注记 / D5 ephemeral_context` 与本轮**无冲突**，可夹带在 C 批或 RT9 之后落。
