# 审计屏 · 一轮的流程（P6）· 供审查

> 只做方案，不写功能代码。本文所有数字都由本次会话在冻结 payload 上现跑得到，
> 跑法见 §九 附录（脚本在 `.scratch/p6a-*.mjs`，只读，没改任何被禁文件）。
> 上一份方案 `docs/plan-audit.md` 的四层与 6 步是本文的地基，本文只动 **L2 的内容组织**。

**一句话结论**：他抱怨的「顺序、分几步、每步在干什么」这三件事，数据里**全都有**，
只是这一屏一次都没读：`stage` 有、`step`（写侧给的管线序号）有、行 `latency` 有、
`stageDetail` 里有 `candidates / total / ms / beginAt / settleAt / ok`。现在 L2 的「阶段链」
（`views/audit.js:577-590`）只把它们连成一行 `assemble › retrieve › tool:pwsh`，
既没有顺序语感、也没有时长与因果。改法不是加一张图，是把这一轮的**行**按时间顺序读成**步骤**。

### 1.3 三条会直接改设计的读数

1. **p50 = 1 步。** 这一窗是执行器窗口（`stage` 直方图：`retrieve 48 / tool:pwsh 40 / tool:edit 20 /
   emotion_decay 15 / send_message 14 / session-reaper 13`），**没有一轮是 `relay_in`**。
   所以任何「固定九格 / 固定流程图」在这屏上 84% 的时间是一格半空的框（这正是
   `plan-audit.md:47-48` 弃掉九阶段图的理由，今天仍然成立）。
   ⇒ **流程必须是「发生过几步就几行」，长度可变；一行轮退化成一行，不许出现空壳结构。**
2. **同一轮的行可以隔 600 秒。** `507bde10` 的三次 `retrieve` 相隔 10 分钟。
   ⇒ 时间轴只能当**文字**（时钟列）出现，不能当**长度**出现；也**不许**把 10 分钟后的第二次检索
   写成「重试」——数据只能证明"又跑了一次"，证明不了"因为失败重来"。
3. **失败是"静默"的。** 3 行 `ok:false` 的 `error` 与 `reason` 全是 `null`。
   ⇒ 失败行必须写「失败（没留原因）」，不许写「失败：null」，也不许只印一个红字。

### 1.5 旧方案的两条禁令，怎么办

## 二、三个方案（差异在信息组织与阅读顺序，不在配色）

### 甲 · 步骤账本：一行一步，就地重做 L2 的行清单

把「阶段链」整段删掉，把「行清单」升级成**这一轮经过**：第 N 步 / 时钟 / 阶段名 / 一句话动作 / 耗时 / 状态。
每行仍是那颗能点开的按钮（L3 的入口不变），所以**不是新加一块，是把已有两块合成一块**。
阅读顺序 = 她做的顺序，从上到下；块标题一行给出「N 步 · 最慢 X（第 k 步 …）」。
代价：L2 变高（8 步轮 +≈290px），「行清单」这个词从屏上消失（文案要改），1440 之外要放弃原始名。

### 乙 · 摘要先行：一句人话流程 + 默认收起的明细

L2 第一行是一句能读的流程：「她起头 → 检索 10 条 → 注入 2088 字 → 发到 QQ → 结构化产出」，
步骤明细默认收起，点开才铺。阅读顺序：先一句、再下钻。
代价：一句 40 字装不下 6 步（本窗最长 8 步），必然要二次点击才看到"每步在干什么" ——
**正是他这次抱怨的那件事**；而且它只是把现在的阶段链换了词，结构风险最低、收益也最低。

### 丙 · 按阶段归并：同一步合成一格，段内只报计数

按 `N2S` 排一轮真实发生的段：`2 检索 ×3 · 3 组装 · 4 工具 改文件`，每段一行、段内报次数与最长耗时。
阅读顺序 = "她这次走了哪几段"（旧面板 `audit-cards.html:159-174` 的做法，但去掉了固定九格）。
代价：**丢时间顺序**（实测 3/141 轮顺序与阶段序不一致），且 p50=1 段时这屏只剩一行；
三次相隔 10 分钟的检索在 `×3` 里分不出先后，与证据 1.3 第 2 条打架。

## 三、选甲，理由与被放弃的代价

**选甲。** 三条都落在证据上：

1. **他要的三件事在一行里同时成立**：顺序（行序=时间序，141/141 单调）、每步在干什么
   （`whatOf` 在冻结 payload 上实测 197/200 = 98.5% 能写出一句话，见 4.5）、
   哪一步最慢/失败（单步 `latency` + `failureOf`）。
   乙把"每步"推到二次点击后面，丙把顺序丢掉 —— 都只解决一半。
2. **84% 的轮只有一行，甲天然退化成一行**（标题「1 步」+ 一行），不会像九格那样出现空壳；
   丙会把这一行浪费在「×1」上。
3. **工程上它是最小改动**：`.au-rowitem` 那颗按钮（`app.css:854`、`aria-expanded/aria-controls` 全链、
   `data-row` 指到 L3）**一个字节都不动**，只在它里面加两格。所以
   `docs/screenshots/p5a-check.mjs` 的 30 项、`p5b-check.mjs` 的 15 项（都按 `.au-rowitem` 定位，
   见 `p5a-check.mjs:120,205,324,376,393,415,455`）不会因为这次改造而失效。

**放弃乙的代价**：读者要多点一次才能看到细节；如果日后他只想"扫一眼"，还得回头做它 ——
本轮不做，记在这里备查（不写进不做清单，因为它不是"不该做"，是"下一轮再说"）。
**放弃丙的代价**：没有「她这次走了哪几段」的高层视图。补法是**不加块**：块标题那一行
（`N 步 · 最慢 X（第 k 步）`）已经回答了"几步 / 卡在哪"，丙想给的第二条信息（走了哪几段）
读那几行的阶段名就有。

## 四、选定方案：结构与草图

### 4.1 与现有四层怎么并（不许把 L1 变成长卡片墙）

**只在 L2 内部换内容，不加新层，L1 一个像素不动。**

```
L0  屏首     需要看 N + chips                    不动
L1  一轮一行  时间 / 类型 / 一句话 / 次数·耗时    不动（不加"流程条"、不加卡片）
L2  展开一轮  这一轮 → 他说了什么 → 她说了什么 →
              ★ 这一轮经过（N 步）               ← 原来这里是「阶段链」+「行清单」两段，现在合成一段
              注入记忆                          不动
L3  点开某步  21 键字段表                        不动（入口仍是那一行的按钮）
```

原来 L2 里「阶段链」（一行）+「行清单」（若干行）是**两段说同一件事**：链说的是这些行，
行说的是行本身。合成一段之后净高度**略降**（少了标签行与链行），且信息全在（§1.4 的断点逐条补上）。
「P6 只改 L2 内部」这条同时满足派单的「新增一个流程条在 L1 与 L2 之间」的**排除项**：不做。

### 4.2 一轮的流程长什么样（具体）

**块标题（一行，12px 灰，与 `.au-meta` 同一档）**

```
这一轮经过 · 7 步 · 轮外 1 · 最慢 1.1 秒（第 3、5 步）
```

- `N 步` = 这一轮的行数（行就是步，恒等，可当场数）。
- `最慢` = 单步耗时最大的那一步，用现有 `durationText`（`audit.js:502-507`）的写法；
  一步都没有耗时量时整句省略，**不写「最慢 —」**。
- **并列要合并**：耗时按 `durationText` 显示成同一串时（例：`9515d152` 的 `query_expand 1111ms`
  与 `assemble 1101ms` 都显示「1.1 秒」），写成 `（第 3、5 步）` —— 否则屏上写着"最慢 1.1 秒"
  而每个 1.1 秒的行都像被点名，读者会以为屏算错了。
- 若该轮有轮外行（见下表末二行），改写成 `7 步 · 轮外 1`。
- 若该轮 `step` 序与时间序冲突（本窗 3 轮），后面补一句 `（从第 9 步的情绪关怀起）`。

**步骤（每步一行；行 = 原有那颗按钮，加了 4 格）**

真样本：`9515d152`（本窗 8 行的那一轮，主动开口 + 两条并行支 + 一次失败），本地时钟 UTC+8：

```
1  15:21:46  关怀         她想你了，主动开口                                  —              （空）
2  15:21:47  情绪打分      与主流程同起，1.1 秒落定 · 没给结果（没留原因）     1.1 秒          并行 失败
3  15:21:47  查询扩展      与主流程同起，1.1 秒落定                             1.1 秒          并行
4  15:21:47  检索          检索到 10 条候选                                    —              （空）
5  15:21:47  组装          注入 2088 字，人设 1796 字在场                       1.1 秒          （空）
6  15:21:49  送信          发到 QQ 私聊，她等了三十五分钟才开口的一个问句        —              （空）
7  15:21:53  结构化产出    记下三个关键词：等回复 / 吃饭问候 / 没回音           9 毫秒          （空）
   15:22:09  会话清理      清掉 1 个会话，留下 48 个                          —              轮外
```

（上面是语义示意；不印圈码，序号是阿拉伯数字，排版见 4.3。第 3 行「查询扩展」在这一轮没有
`reason: cache_hit`（`7719f842` 那一轮才有），所以没有"命中缓存"这半句 —— 一句话也得只写这一步真有的事。）

**六格的含义**

| 格 | 内容 | 取值来源 |
|---|---|---|
| 序号 | 1..N，主流程行连续编号；轮外行不带号 | 行在 `turn.rows` 里的位置（= 时间序） |
| 时钟 | `HH:MM:SS` | `stampOf(row.timestamp)`（`audit.js:478-483`） |
| 阶段名 | 人话（8 字内），原始名 1440 才印在它右边 | `humanOf`（`:166-169`）+ `HUMAN_FALLBACK`（`:158-164`）+ `N2S` |
| 一句话动作 | ≤40 字，**这一步做了什么** | 新函数 `whatOf(row)`，见 4.5 |
| 耗时 | 单步时长；`latency > 0` 才印，否则 `—`（`0` 与 `null` 都印 `—`，两者在 L3 里照原值分开印） | `row.latency` 优先；`stageDetail.ms` 次之（并行支只有这个） |
| 状态 | 慢 / 失败 / 并行 / 又跑了一次 / 轮外 | 见 4.5 |

**并行 / 重复 / 跳过 / 失败怎么表示（这是判分点）**

| 情形 | 怎么画 | 为什么 |
|---|---|---|
| 并行（`step 21/22`） | 按时间**插在原位**，行首加「并行」，左缩进 16px 表示支线；句末写 `起跑 15:21:46.548 · 落定 15:21:47.635（1.1 秒）` | 它真的与主流程同时跑（`beginAt` 相同），挪到末尾就是骗人；不画轨道（证据 1.2 的 0.01） |
| 同名相邻多次（`507bde10` 的 3×检索） | **不折叠**，逐次一行，第 2 次起句末加灰字 `又跑了一次 · 距上一步 10 分 10 秒` | 数据能证明"又跑了一次"，证明不了"重试"（1.3 第 2 条） |
| 跳过的步骤 | **不画**。没有的步骤不占位、不写"这轮没发生" | `plan-audit.md:47-48` 的原判据继续成立 |
| 失败 | 该步行末红字「失败」，括号里写**信号**：`ok=false` / `超时` / `error` 的前 40 字 / `丢了 3 条三元组`；信号没有原因时写「没留原因」 | 本窗 3 行都是 `ok:false + error:null`；写成「失败：null」是编 |
| 慢 | 单步 `latency ≥ 30000`（与 L1 同一个 `SLOW_MS`）→ 行末灰字「慢」 | 与 L1 同阈值，屏上不会出现两种"慢" |
| 轮外 | 排在主流程之后，组尾一行小字「轮外」，不带序号 | `stepOf === 0`（如 `session-reaper 13`、`ipc-appraise 3`）：管线表里没有它的位置 |
| 步数 > 12 | 先列 10 行 + 一颗「还有 N 步」按钮 | 防病态轮把 L2 变成墙；本窗最多 8 行，这条只是护栏 |

### 4.4 顺序从哪来（规则写死，冲突怎么办）

1. **主序 = `turn.rows` 的下标顺序。** 它就是时间顺序：`buildTurns` 在 `audit-view.js:318` 先按
   `timestamp` 全局升序排完，再 `:425` 按到达顺序 `push` —— 实测 141/141 单调、0 处并列。
   **本屏不自己排序**（不 `sort`、不按 `step` 重排）。
2. **序号 = 位置（1..N）**，不是 `step` 的值。`step` 是**管线位置常量**（`relay_in 1 / retrieve 2 /
   assemble 3 / tool 4 / structured_output 5 / 送信 6 / extract 7 / longing_steer 8 / care 9`，
   `web/audit-cards.html:108` + `lib/index.js:3672-3673`），用它当"第几步"会印出「第 9 步 → 第 21 步 → 第 2 步」这种废话。
3. **`step` 只用来做两件事**：判「轮外」（`stepOf === 0`）、给阶段取名（`stepOf` 的四级回退：
   `step → toolCall → stage`，`tool:structured_output` 归 5 不归 4 —— 全部照抄 `audit-cards.html:113-125`，不自己发明）。
4. **冲突（`step` 序与时间序不一致，本窗 3/141）**：不重排，只在块标题补一句
   「（从第 9 步的情绪关怀起）」。读者要知道"这一轮是她起头的"，而不是让屏替她重排因果。
5. **时间戳并列**：按数组序，句末标「同一时刻」（本窗 0 处，规则先立在，免得日后无声乱序）。
6. **时间戳缺失（0/负）**：排在这一轮最后、组尾「时间不明」（本窗 0 行）。
7. **并行支行不许挪位**：按时间插在原位（见 4.2），因为它们与主流程同时起跑。
