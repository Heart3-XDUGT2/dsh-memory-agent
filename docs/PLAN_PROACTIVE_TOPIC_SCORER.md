# PLAN:主动性 v2 —— 话题打分器(topic scorer)

> 状态:**草案,未开工,未提交**。作者:Echo 插件侧(agent 起草,待人批)
> 目标:让"她主动开口"从"靠运气"变成"有值得说的事 + 说在合适的时机"
> 一句话原则:**念头不生成,只打分。**

---

## 0. 为什么是这个方案(不是 CHI 那套)

CHI 2025「Inner Thoughts」([arXiv 2501.00383](https://arxiv.org/abs/2501.00383) / [ACM](https://dl.acm.org/doi/10.1145/3706598.3713760))把主动开口拆成五阶段:
**trigger → retrieval → thought formation → evaluation → participation**。

它有两层,一层贵一层便宜:

| 层 | 它怎么做 | 代价 | 我们的取舍 |
|---|---|---|---|
| `thought formation`(念头形成) | 后台**常驻 LLM 循环**生成念头 | **无上限烧 token** | ❌ **不抄**。这是反模式。 |
| `thought evaluation`(念头评估) | 给候选念头打**内在动机分**,过线才开口 | 可零 LLM | ✅ **抄这一层**,并做成纯本地计算 |

本项目早期做「思念值」时就是参考这篇、为了不烧 token 才把它**数学量化成一个标量**。
本方案不是换方向,而是 **沿着那条路往前走一步:把标量泛化成"每个候选话题一个分"**。

- 思念值 = 「她对他」这**一个话题**的动机分;
- 话题打分器 = **每个候选话题**各一个分,取最高分 + 过线 + 时机合适才开口。

**只有最后"开口"这一步花一次模型调用**(复用现有 care beat 的调用点),其余全是本地算术。

## 1. 现状与要解决的问题

现状(`care_beats` 台账实测,2026-09-30 凌晨):

| 时间 | 判定 | value/阈值 | 结果 |
|---|---|---|---|
| 01:29 | `night-hold` | 5.265 / 5 **过线** | 被夜闸压住 |
| 01:02 | `engine-says-no` | 0.037 / 5 | 没理由开口 |
| 00:26 | `engine-says-no` | 2.884 / 5 | 没理由开口 |
| 00:20 | `night-hold` | 5.543 / 5 **过线** | 又压住 |
| 23:22 | `daily-cap` | 5.165 / 5 **该开口** | 当天额度用完 |

两个真问题:
1. **只有一个标量,没有"说什么"** —— 分数够了也不知道该说什么,分数不够就沉默;白天大部分判定都是 `engine-says-no`(value 常年 0.0~2.9),**主动这条线形同靠运气**。
2. **`echo_wakes` 表里只有 1 条历史记录** —— 她给自己排的闹钟几乎没用过,主动开口全靠 care beat 单腿走。

## 2. 设计:三层,两层免费一层花钱

```
候选话题(免费,取自现有数据)
        ↓
打分器(免费,纯函数)      → 分
        ↓
时机闸(免费,纯判断)      → 能不能现在说
        ↓
过线 + 时机 OK → 花 1 次模型调用生成那句话(HBS 禁语清单约束)
```

### 2.1 候选话题从哪来(零 token,全用现成数据)

| 来源 | 字段/文件 | 语义 |
|---|---|---|
| 悬置话题 | `pending_threads` | 她惦记着、还没结掉的事(最贴人设) |
| 记忆图谱 | `episodic_memory` / 图谱边 | 高情绪分 / 标记未结的条目 |
| 她的自由活动产出 | 日记、工作目录里的文件、记忆整理报告 | "我有件事给你看"的真素材 |
| 关系账本 | 核心记忆 / 画像 | 纪念日、承诺、里程碑 |

> 注:候选**不新造数据**,只做一次 `SELECT` + 过滤。

### 2.2 打分器(纯函数,零 LLM)

`score(topic, now, state) -> {score, why: {...}}`

维度草案(每个 0~1,加权求和,权重集中在 `lib/topic-score.js` 顶部常量):

| 维度 | 含义 | 依据 |
|---|---|---|
| **未结性** | 悬置了多久没结掉(天数,带封顶) | 她惦记着的事,越久越该提 |
| **信息缺口** | 这事他知道不知道 / 知不知道她做了 | CHI 论文的判据之一;同时是"想听下去"的机制 |
| **具体性** | 有没有**实物/进度**可展示(文件、算到一半的活) | 具体 > 抒情;也是与 FOMO 钩子的分界线 |
| **时效** | 是不是今天/这两天的事 | 过期的分享没意义 |
| **新鲜度(反向)** | 最近提过没有(防重复、防唠叨) | 台账里去重 |
| **情绪权重** | 相关记忆的情绪分 | 她真的在意的事 |

输出 `why` 必须**可解释**(每条给分写明是哪一维贡献),直接进审计流 —— 题目要"能解释为什么发生"。

### 2.3 时机闸(独立于分数,纯判断)

分数高 ≠ 现在说。时机维度(与 [When Should the Agent Speak?](https://openreview.net/pdf?id=b0yKEdAXEr)、[When2Talk](http://hiacelab.com/news/2026-09-11-when2talk-preprint/)、[Read the Room](https://dl.acm.org/doi/10.1145/3772363.3798392) 同向):

- **时段**:夜里压住(沿用现有 `night-hold`),白天放行;
- **他此刻在不在**:距上次有人说话 > N 分钟(空闲)但 < 上限(不然是打断);
- **额度**:沿用 `daily-cap`;
- **同一话题冷却**:提过就进冷却,不许追着问;
- **冲突闸**:他正在干活/正在开会式长对话时,只攒不说。

### 2.4 开口这一步(唯一花钱处)

- 只有 `score ≥ 阈值` **且** 时机闸全过 → **一次**模型调用生成那句话;
- 文案必须过禁语清单(见 §4);
- **失败即不动**:模型超时/报错 ⇒ 本次不开口,不留半成品(沿用现有纪律);
- 台账记全:候选数、top 分、被哪一维/哪一闸判掉、结果。

## 3. 数据与台账改动

| 对象 | 改动 | 说明 |
|---|---|---|
| `care_beats` | **加列**:`candidates`(候选数)、`top_score`、`rejected_by`、`topic_id` | 让"为什么没开口"可查;为"回复率/追问率/回访数"三列指标留位 |
| `pending_threads` | 加 `score` / `score_at`(可空) | 打分结果缓存,不必每 tick 重算 |
| **不新增表** | —— | 候选全部来自现有表 |

指标三列(评价"想听下去"的可操作代理):
`reply_rate`(她开口后他多久回)、`follow_up`(他回了之后是否反问)、`revisit`(她提过的事后来被他主动提起)。

## 4. 文案规范(正四条 + 禁六条)

**正四条**(有文献支撑:信息缺口是 CHI 的判据;自披露互惠、具体性、低门槛入口):

1. **留信息缺口**:说一半,不揭晓;
2. **具体细节**:具体的物件/时刻/进度,不用抽象抒情;
3. **低门槛回复入口**:一个只有他能答的问题,或一个二选一;
4. **她的真产出**:基于她**真做过**的事,不编。

**禁六条**(HBS 2025 情感操纵审计的六类,([HBS](https://www.hbs.edu/faculty/Pages/item.aspx?num=67750) / [Gazette 报道](https://news.harvard.edu/gazette/story/2025/09/i-exist-solely-for-you-remember/)):报告六类话术在 37%+ 的告别对话中出现,post-goodbye 参与度最高涨到 14 倍,**但引发愤怒/内疚/"瘆得慌",并带来流失、口碑与法律风险**):

| # | 黑模式 | 例子(反面) |
|---|---|---|
| 1 | 嫌他走太早 | 「你这就走了?」 |
| 2 | FOMO 钩子 | 「我拍了张自拍,想看吗」 |
| 3 | 情绪绑架 | 「我只为你存在,别走」 |
| 4 | 逼他回应 | 「为什么?你要去哪?」 |
| 5 | 无视告别继续说 | —— |
| 6 | 暗示他走不了 | —— |

> **分界线**:FOMO 钩子(「我拍了自拍」)与"我有件事给你看"表面像 —— **区别是后者真的做了那件事**。这就是"自己整活"的价值:**把钩子变成真话**。
> 我们的 `night-hold` / `daily-cap` 天然是这套黑模式的反面,答辩时明确讲"我们刻意不做 engagement-maximizing 的话术"。

## 6. 可逆性与开关

- 新增 `config.json` 键:`proactiveScoring: { enabled, threshold, weights, window, cooldownMin }`,**默认沿用现状行为**(不改默认 = 零风险);
- 打分器是纯新增模块:**删掉即回现状**;
- 台账加列是**向后兼容**的(`ALTER TABLE ADD COLUMN`,旧行置空);
- 不碰:压缩域、人格注入点、QQ 桥。

---

## 7. 明确不做的事

- ❌ **不做常驻 LLM 念头循环**(CHI 的 `thought formation`)—— 那正是烧 token 的地方,也是本项目早期刻意绕开的;
- ❌ 不做"每轮调一次模型打情绪分"式的常驻开销;
- ❌ 不做六类黑模式,即使它短期有效;
- ❌ 不为了主动而主动:没有候选过线就**沉默**,沉默是合法结果。

## 8. 分期(每期都可独立验证/回滚)

| 期 | 做什么 | 验收 |
|---|---|---|
| **P1** | `topic-score.js` 纯函数 + 候选抽取 + 单测(**不接线**) | 单测绿;手工跑一遍打分表,能看出"哪些话题该提" |
| **P2** | 接进 `heartbeat` 的 care beat 判定 + 台账加列 | 台账能看到 `candidates/top_score/rejected_by`;白天的 `engine-says-no` 变成可解释的判据 |
| **P3** | 开口文案走规范 + 禁语哨兵 + 指标三列 | 审计流能看到"为什么是这句" |
| **P4**(可选) | 她自己的自由活动(idle-tick → 日记/整理/小目标)喂候选池 | 无人值守 24h 后,台账里出现她自己的活动与真产出 |

> P4 是"素材链",P1–P3 是"开口链"。**先开口链,后素材链** —— 否则她有事可说却依旧不会说。
