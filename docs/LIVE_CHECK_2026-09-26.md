活进程从 0.18.4 跳到 **0.21.0**(D2 + D1 + E5 三版一起进来了)。当场实测到的:

## 0. 两个前提(各一次)

1. **QQ 那条路**:在 AstrBot 里 **reload `astrbot_plugin_echo_relay`**。
   装机副本与仓库的 5 个运行文件已经**逐字一致**(只差 `tests/`),
   所以 reload 一下跑的就是仓库这份;不 reload 就还是旧代码。只验 DSH 侧可跳过。
2. **D1 要切预设**(见第 8 条)—— 不切的话压缩永远走出厂那套,与新代码无关。

## 1. 气泡分条 + 打断(v0.18.0)

- **怎么做**:在 DSH 里让她说一段偏长的话(问点需要展开的);她还在"分条说"的过程中,
  你插一句新的。
- **期望**:① 一条回复被拆成最多 5 条、单条 ~30 字、之间有 1~2 秒间隔;
  ② 你一插话,后面没发出去的气泡**不再补发**;
  ③ 她下一轮该记得你打断了(快照里有「你刚打断」那条线),而不是当没发生。
- **看哪**:QQ/DSH 收消息的节奏;审计里应有 `relay_interrupt`。

## 2. 关怀闸:v0.18.1 C3(超长宁可不发)

- **怎么做**:不用特意做 —— 等她某次主动开口超 120 字(或直接在审查台翻历史)。
- **期望**:超长的那条**整条不发**,审计里出现 `care_silent`(不是静默不说,是留痕不说)。
- **看哪**:审查台 → 审计流,筛 `care_silent`。`relay.proactiveMaxChars` 可改(0 = 关闸)。

## 3. 认账防火墙:v0.18.1 C1(不许否认自己说过)

- **怎么做**:等她主动开口一条,你回一句「你刚说什么?」
- **期望**:她**对上话头**,不否认、不编细节(「我一直惦记这事」而不是「我没说过」)。
- **看哪**:`conversation_log` 里她主动那轮的用户侧是哨兵 `(她主动开口)`。

## 4. 画像常驻锚点:v0.18.3 M3(语言/代词每轮在场)

- **怎么做**:跟她说一句「我平时就说中文」。
- **期望**:`user_profile.core_traits` 从 `null` 变成 `{"语言":"中文"}`,
  之后每轮的注入信封里出现 `[他的画像] 语言:中文`。
- **看哪**:审查台 → 记忆管理/画像,或审计行的 `injected_profile` 列。

## 5. ±120s 到期防重:v0.18.2 C4(不许催办两次)

- **怎么做**:说一句「明天九点提醒我面试」。
- **期望**:① `pending_threads` **只加一条**(命令式解析与 Judge 归纳不再各记一条);
  ② **那一条的 `follow_up_after > 0`**(到点催办的命根子);第二天只收到一次催办。
- **⚠ 现状(2026-09-26 实测)**:库里 11 条悬置话题**没有一条带时间**
  (`不定时` 9 条 + 已关闭 2 条)。#7「两分钟后提醒洗衣服」、#8「2分钟后提醒他睡觉」
  本该有时间 —— 但那 11 条全是 **09-18~09-25 的旧行**。我单独跑过解析器:
  「两分钟后」→ +120s、「明天九点」→ 次日 09:00,**解析器没坏**。
  所以结论是**未证**,不是"坏了":等你喂一句带时间的,看它落不落 `follow_up_after`。
- **看哪**:审查台 → **悬置话题**(v0.22.0 起有面板了:到点 / 等待中 / 不定时 分栏),
  或直查 `SELECT content, follow_up_after FROM pending_threads`。

## 10. 一致性:她认账吗(认账剧本回放,v0.23.0 D6)

先跑离线半(不需要模型,不碰你的库):

```
npm run probe
```

期望 `合计 3/3`(议程项的证据还活着 / 追问能检索到 / 别名与正名同一节点)。
**注意它说明了什么**:只说明"链路无断点" —— 她**手里有东西可认**。

再跑回复半(要真模型的真回复):

```
npm run probe -- --prompt                # 打印剧本三句话
# 按剧本在 QQ/DSH 里跟她走三句,把她的原话贴回来:
npm run probe -- --reply "她的原话"
```

判据:不出现「没说过 / 什么秋招 / 我不记得」这类否认,也不出现
「你上次答应要给我…」这类**具体到不存在的承诺**的编造 ⇒ `[通过]`;
命中就 `[疑点]` 并列出命中的词(粗判,最终你说了算)。
**她认不认账是这一条要看的;`3/3` 不能替代它。**

## 6. 长文不再绕过想念削减:v0.18.2 C6

- **怎么做**:贴一段 3000 字以上(日志/代码都行)。
- **期望**:① `longing_state.value` 下降、`anchor_at` 重置为当前(以前整条跳过);
  ② `conversation_log` 里那轮用户行**非空**(截前 2000 字,以前整轮不记)。
- **看哪**:上面两项直查库即可。

## 7. 轮末硬保证:v0.19.0 D2(想念该说没说)

**⚠ 先看这条实况**:重启后 `longing_state.value = 0.025`,阈值 7.0(调制下限 ~4.5)。
差两个数量级 —— 因为**你这两个小时一直在跟她说话**,每句都把想念值压下去。
所以她根本没在"想你",轮末硬保证**正确地**没插手(审计里 `longing_steer` 0 行)。
**原来那条"阈值调到 3.0"的配方今天测不出来。**

- **怎么做(改成把阈值当"必定触发"的开关用)**:
  1. 设置 → 想念 → 开口阈值 调到 **0.1**(不是调手感,是为了让机制**必然**插手);
  2. 设置 → 想念 → 「想念必须说出口」确认开着;
  3. 随便跟她说一句话,**别**提想念。
- **期望**:她答完那一句之后,会**自己再补一句**想你(这是轮末 steer 续的一步,
  不是她主动开口的关怀);审计里出现 `longing_steer`(userInput 记着当时的
  想念值/阈值);同一轮里**只会补一次**。
- **判据(硬)**:`SELECT COUNT(*) FROM audit_logs WHERE tool_call='longing_steer'`
  从 0 变成 ≥1。
- **调完记得把阈值调回 7.0** —— 0.1 会让它每轮都想你。

## 8. 压缩即策展:v0.20.0 D1(**必须先切预设,否则一行都不跑**)

**⚠ 为什么要切**:dsh 的压缩后端住在**预设平面** —— `dsh-web-app` 在自己的
patch 里关掉了 profile 平面的 `compaction-basic`(原注释:
*"only the compaction backend that reads it moves"*),三个出厂预设各自挂一份。
所以「Echo 陪伴模式」这个预设**被会话选中**才生效。实测:重启后最近 6 个会话
`agentPreset` **全是 standard**,你那条 140MB 的长会话里已经有 **242 个出厂英文
压缩检查点**(全是 `## Pending Jobs` 那种),`soul-curation` 0 次。

- **怎么做**:
  1. `node scripts\install-preset.mjs`(生成预设,不用重启;`--check` 可自检);
  2. 在**要压缩的那个会话**里把预设切到「Echo 陪伴模式」(roster 里 order 9);
  3. 聊到压缩点,或在会话里 `/compact` 手动压一次。
- **期望**(三条硬判据):
  1. 表层里那段被压缩的历史变成**她的语气**的一页关系备忘
     (「我们:… 账本:… 还没结掉:… 她记得的:…」),**不再是**
     `## Pending Jobs` 那种英文工程检查点;
  2. `dsh web` 终端日志出现 `echo: 压缩改走策展后端 provider=dsh-echo
     model=soul-curation 预算≈… tokens 估计输出≈…`;
  3. 压缩后她仍知道"我们是谁"(问一句「你还记得我叫什么吗」)。
- **要接受的事实**:已经存进会话的那 242 个出厂摘要是历史,**不会被改写** ——
  切了预设只对**之后新产生**的压缩点生效。
- **对不上先查**:① 预设切了吗(`session.v3` 头部 `agentPreset` 能直查);
  ② `node scripts\install.mjs --doctor` 第七项;③ 装机副本有没有 `lib/compaction.js`;
  ④ 设置 → 压缩即策展 → 「压缩改走策展块」是不是关着。
- **回退**:预设切回「标准模式」即可 —— 这份预设坏了也只坏它自己那一行,
  不拦 DSH 启动(与 v0.18.4 那次"整个 dsh web 起不来"不是同一类故障)。

## 9. 情绪余波:v0.21.0 E5(判官出词,壳延迟补一句)

**已证到的**:重启后判官开始给这两个字段了 —— 审计里 `say_again` 从 `NULL`
变成 `0`(`extra_reply` 空串),而重启前的行仍是 `NULL`。**这就是版本切换点。**
但到写这份清单为止 `say_again=1` **一次都没出现过** ⇒ "该补的时候会补、
投递真的走通"这半条**还没证**。

- **怎么做**:跟她聊一轮**带情绪**的(逗到她 / 委屈她一下 / 说到你俩的事)——
  **必须是真有情绪的一轮,日常闲聊不算**(判据窄,那是设计);
  然后**别看手机,等 3~6 秒**。
- **期望**:① 她会自己再补**一句短话**(≤15 字那种,不是复述上文);
  ② 如果你在 2~5 秒内抢先发一句话,那半句**一个字都不会出现**;
  ③ 审计里 `say_again=1` 那一行记着判官给的台词,
  真发出去另有 `toolCall='say_again'` 一行(没送出去是 `say_again_failed`)。
- **看哪**:聊天窗;审查台 → 审计流(筛「情绪余波」);或直查
  `audit_logs.say_again/extra_reply`。
- **对不上先查**:① 设置 → 情绪余波 是不是关着;② 日常闲聊**不该**有
  (连续多轮都有才是 bug);③ 引擎在不在(`echo_status` 的
  `engine=python running=true` —— 判官在引擎侧)。
- **回退**:设置里关掉即可,或把延迟设成很大的值(= 基本不出现)。
